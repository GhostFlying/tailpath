## Restart and storage

- Relay collector restart completed and the subsequent relay workload reported
  normally without a catch-up spike.
- Relay runtime restart temporarily fell back to DERP. Relay telemetry returned
  online, and a new workload then proved both endpoint paths recovered to Peer
  Relay at the expected workload scale.
- Server restart recovered the API while preserving the canonical business
  edge; the 15-minute History list remained non-empty and its detail remained
  queryable.
- History retained traffic points and an ordered
  `direct -> peer_relay -> direct` transition. Genuine intermediate events from
  the reused lab and restart recovery were not removed.
- A passive endpoint used only by relay telemetry supplied the privacy canary.
  Its underlay address was absent from SQLite, WAL, and SHM. Ordinary Direct
  endpoint addresses were intentionally excluded because the security contract
  permits their persistence.

## Residual

No runtime or storage blocker remains in this candidate. Relay telemetry may
observe collector delivery traffic when that delivery path itself uses Peer
Relay; this is intentionally retained as internal provenance and excluded from
the default Live business graph by the dedicated control identity behavior
tracked in the merged #109 change.
