## Restart and storage

- Relay collector restart established a fresh counter baseline before reporting
  new traffic.
- Relay runtime restart temporarily fell back to DERP. Passive status returned
  to Peer Relay after 25 seconds; a new workload then proved relay telemetry at
  the expected workload scale.
- Server restart preserved its tsnet address, canonical business edge, three
  one-hour History entries, path set, and byte total exactly.
- History retained traffic points and an ordered
  `direct -> peer_relay -> direct` transition. Genuine intermediate events from
  the reused lab and restart recovery were not removed.
- A passive endpoint used only by relay telemetry supplied the privacy canary.
  Its underlay address was absent from SQLite, WAL, and SHM. Ordinary Direct
  endpoint addresses were intentionally excluded because the security contract
  permits their persistence.

## Residual

Relay telemetry can observe collector delivery traffic when that traffic uses
Peer Relay. [Issue #109](https://github.com/GhostFlying/tailpath/issues/109)
tracks the required server-side exclusion. This does not alter the correctness
of the business-session evidence above, but it violates the accepted dedicated
control-identity contract and must be resolved before the v0.3 release closes.

The immutable candidate run started the server before its collectors, but it
did not preserve a mixed-version window proving that older ordinary collectors
continued to report to the candidate server. That compatibility acceptance
item remains open and requires a focused rerun against an older collector
artifact.
