# v0.2 usable alpha execution plan

Status: active
Issue: https://github.com/GhostFlying/tailpath/issues/18
Milestone: v0.2
Last updated: 2026-08-23

## Context

v0.1 proved the passive collector-to-graph vertical slice. v0.2 turns that
slice into the first daily-usable alpha while preserving the passive
observation boundary and best-effort inventory semantics.

## Goals

- Make the Linux Compose server and Linux collector usable in ordinary
  operation, and validate the macOS collector on a real arm64 Mac.
- Ship a buildable and installable but explicitly unverified Windows preview.
- Keep the Live graph stable through updates and add a bounded seven-day
  History workspace.
- Harden collector recovery, storage recovery, and browser invalidation.
- Establish deterministic 250-node/1,000-edge functional and performance gates.

## Non-goals

- Peer Relay server telemetry or public tsnet/tsbridge exporter packages.
- A complete Tailnet device directory or mandatory Devices API integration.
- Active probes, packet capture, or traffic generated for path discovery.
- A supported backup or restore contract.
- MSI, package-manager publishing, code signing, tags, or GitHub Releases.

## Decisions

- Observer protocol remains version 1. Platform metadata is optional display
  data and never participates in identity reconciliation.
- Collector flags override environment values, which override built-in
  defaults. v0.2 does not introduce a YAML configuration file.
- The server heartbeat is the only freshness setting and must be between ten
  seconds and ten minutes; edge, observer, and node windows remain derived.
- History is traffic history, not topology replay. It retains at most seven
  days and exposes fixed windows and resolutions.
- Browser-local canonical-node coordinates stabilize Live layout. Relay and
  unknown path markers remain derived and are never persisted.
- Releases are two-stage and human-owned: `v0.2.0-alpha.1` for immutable
  dogfood artifacts, then `v0.2.0` after dogfood, review, and blocker fixes.

## Interfaces

- #22 adds collector environment variables and passive `collector --check`.
- #23 adds optional `os` fields without changing protocol version 1.

- #26 adds `/history` and `/history/edges/:edgeId` as lazy-loaded web routes.
- #27 adds platform-specific archive install and uninstall scripts.

## Tests

- PR checks use deterministic functional scale smoke plus focused Go, API,
  React, Vitest, and Playwright coverage.
- A manual workflow enforces ingest, API, database-size, browser-startup, and
  SSE latency gates under a 2 vCPU and 512 MiB container limit.
- Linux dogfood covers Direct to DERP to Direct, restart, resync, and History.
- Real Mac dogfood covers LocalAPI, LaunchAgent startup, Direct traffic, server
  outage, and recovery. Windows remains CI-only preview in v0.2.

## Risks

- Per-report full-state persistence and graph layout can exceed the scale gate;
  #20 establishes a baseline before #21 and #24 optimize them.
- Bilateral observations can double-count traffic; #25 must use the existing
  logical-edge deduplication rule before rollup.
- Canonical merges can split old history; persisted redirects must be resolved
  before grouping or filtering.
- Collector recovery must not turn offline intervals into invented traffic.
- Cross-platform installers can claim more support than was actually tested;
  platform support labels must match dogfood evidence.
