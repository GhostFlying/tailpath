# 系统性排版规则

[English](layout-rules.md) · [UI 风格指南](styleguide.md)

本文是 Live、History、Devices 和共享工作区的排版约束，定义后续 UI 改动应达到的
目标，不代表当前渲染器已满足全部规则。中英文版本必须同步维护。

本次移动端截图中，DERP 标签挤到了设备旁边，右侧设备及名称也过于紧密。这类问题
来自可见元素争用空间：只检查节点中心距离，或统一拉长连线，都没有完整考虑名称、
徽标、中继实体及无关路径的占用。

## 1. 优先级与占用区域

按以下顺序处理取舍：拓扑与身份真实；控件可用、选中上下文可读；实体及必要标签
分离；位置稳定；可选细节；视觉对称与紧凑程度。

- 节点占用区域包括实体、边框、外置名称、遥测／身份徽标及选中／焦点装饰。
  中继也是节点，必须拥有独立占用区域。
- 标签占用区域包括实际文本、背景与内边距。按真实字体、字重、回退字体和显示
  内容测量；字符数只能用于初步估计。字体加载或文字变化后重新检查。
- 连线占用区域包括有宽度的曲线、箭头和速率标签。检查曲线路径，不能只检查两端
  距离。平行连线保留各自通道。
- 控件、展开面板、图例和安全区占用屏幕空间。Fit 基于剩余可见工作区计算，
  内容边界必须包括标签。
- 碰撞检查统一使用平移／缩放后的 CSS 像素。模型坐标须通过当前变换换算；
  不混用设备像素、图模型单位与 CSS 像素。点击区域与绘制区域分别检查。

以下数值是待实现、待验证的项目设计默认值，不是对现有界面的测量，也不是无障碍
合规声明。使用共享的具名 token，避免给单个元素堆叠偏移量。

| 项目 | 默认约束 |
| --- | --- |
| 间距刻度 | 4、8、12、16、24、32 CSS px |
| 无关节点／中继的完整占用区域 | 边界间至少 12 px |
| 无关标签之间、标签与实体之间 | 至少 8 px |
| 无关连线描边／箭头与文字之间 | 至少 4 px，计入标签内边距 |
| 图内容与可用视口边缘 | Fit 后至少 16 px |
| 节点名称与自身实体 | 至少 8 px；锚点有效时保持稳定 |
| 普通设备实体 | 保持现有 52 × 52 图模型单位的形态 |
| 图中名称／可见速率文字 | 可读详情模式下至少 12／11 渲染 CSS px |
| 工作区正文／次要文字 | 至少 14／12 CSS px；行高至少 1.4 |
| 触控控件 | 点击区域至少 44 × 44 CSS px；点击区域不得互相重叠 |

多项规则适用时取较大的间距。徽标可以有意附着在自己的节点上，连线必须接入自身
端点，标签背景可以遮住自身连线的一小段。这些例外不允许覆盖其他对象、方向箭头，
或理解连接所必需的身份信息。

## 2. 文字与信息层级

- 身份、状态、指标使用明确的布局槽位。使用 grid 或 flex 的 gap；先给指标列
  保留空间，再分配名称宽度。名称列允许收缩（`minmax(0, 1fr)`／`min-width: 0`），
  指标列宽度稳定。禁止用 transform 或负 margin 对齐文本。
- 设备名默认单行，初始显示宽度预算为 160 CSS px；只有预留完整高度时才允许
  最多两行。有意识地截断，共同前缀较长时保留可区分的后缀；缩写后仍重复的名称
  必须提供稳定的区分标签。
- 完整身份必须能通过键盘聚焦和触摸选择在 inspector 或可访问的详情视图中查看，
  不能只依赖 hover。选择控件的无障碍文本须包含完整名称。
- 数字与单位不可拆行。使用等宽数字，为常见速率格式切换预留宽度。数值超过预算
  时重新测量标签，但不能因流量更新而移动真实节点。
- 一条逻辑连接最多显示一个紧凑的总速率标签，即使中继把它分成多段。双向速率
  放入 inspector。Recent 路径不保留过期速率或箭头。路径类型与活跃状态保持
  独立视觉维度，并保留非颜色的路径标识。
- 禁止通过缩小字号解决碰撞。总览缩放级别可以明确省略可选标签，通过选择或放大
  恢复。选中名称及详情必须在屏幕坐标的浮层或 inspector 中保持可读。

## 3. 节点、中继与连线

- 检查所有邻近节点的完整区域，包括不相连的节点和虚拟标记。长名称和徽标必须
  参与布局与 Fit 边界计算。
- DERP 胶囊根据显示名称与内边距确定尺寸，并设有文档记录的宽度预算。达到预算
  后截断并提供完整名称。禁止固定宽度胶囊中的文字溢出到邻近设备上。
- 邻居质心只是中继位置的候选点。应在周围按确定顺序尝试替代位置，直到完整中继
  区域避开其他占用，并同步调整各段连线。共享中继不能由最后处理的连接决定位置。
- 保留真实 Peer Relay 身份和 A → relay → B 结构。不得为简化几何关系而合并不同
  中继或虚构直连路径。
- 连线绕开无关节点实体和文字。优先使用短而一致的曲线，为平行或双向流量分离
  入射角。箭头在端点实体外保留辨认方向的空间。
- 速率标签放在足够长且无碰撞的线段上，避开箭头、中继实体和汇合处。先尝试沿
  自身连线的稳定替代位置，再省略可选速率标签。无法避免时允许连线交叉，但交叉
  不能看起来像节点或路径汇合点。

## 4. 冲突处理与密度

按确定顺序、在有限计算预算内处理，每一步都必须保持路径语义：

1. 测量完整占用区域，预留工作区遮挡区域。
2. 复用有效标签锚点，尝试其他锚点及沿线标签位置。
3. 移动虚拟标记、调整受影响连线路径，保持已有真实节点不动。新路径须通过相同
   碰撞检查。
4. 缩短可选名称，省略未选中速率，必要时再省略未选中名称。保留实体和非颜色的
   状态／路径标记；说明细节已减少，并确保选择后可查看完整信息。
5. 初始布局或用户明确点击 Relayout 时，按完整占用区域拉开真实节点；增量布局
   只移动新增节点。
6. 视口仍无法容纳可读详情时，进入明确的总览模式，提示缩放、筛选或查看局部邻域。
   Fit 可以减少细节，但不能把极小文字当成可读结果。

标签空间按选中上下文、键盘焦点／悬停上下文、活跃身份、近期身份、未选中速率的
顺序分配。冲突及时间偏差警告即使把说明移入详情，也保留非颜色标记。同级竞争用
稳定 ID 决定顺序。不能为通过碰撞检查而隐藏整条关系，也不能静默聚合身份。
在可访问的工作区状态中说明省略标签数量或当前处于减少细节的模式。

在项目的 250 个已知节点、1,000 条可见关系规模边界内，不要求总览展示全部标签，
但要求布局计算有界、控件可响应、拓扑真实、选中邻域可检查。允许密集总览中的
连线交叉，不允许选中上下文不可读。

## 5. 稳定性与布局触发条件

| 触发条件 | 允许的响应 |
| --- | --- |
| 速率、活跃状态、SSE 重连、搜索或可见性筛选 | 保持真实节点位置和平移／缩放；重新验证受影响标签与路径 |
| 新增真实节点 | 放置新增节点，已有节点不动 |
| 中继／身份／名称／字体变化 | 重新测量并调整展示，保留已有真实节点位置 |
| 恢复缓存坐标 | 验证完整区域，使用展示降级，不静默重写缓存位置 |
| 尺寸、方向、面板或浏览器工具栏变化 | 重新计算可用区域与标签可见性，保留用户平移／缩放 |
| 首次出现可见拓扑，包括空图后恢复 | 有界初始布局与自动 Fit |
| 用户点击 Fit | 只改变平移／缩放，计算完整内容边界及屏幕遮挡 |
| 用户点击 Relayout | 重算真实节点位置、解决碰撞，再 Fit 并保存 |
| 用户拖动 | 保留用户指定位置，重新验证受影响的展示并保存 |

稳定性不能成为标签重叠的理由。优先在展示层解决；若固定位置或用户拖动导致实体
仍然碰撞，应说明限制并提供明确的 Relayout 操作。降级可以避免打断用户，但不算
通过详情布局的无碰撞验收。不能在下一次遥测更新时偷偷移走用户节点。小幅速率变化
应保持有效标签位置；细节阈值采用滞回，避免轻微缩放使标签反复闪烁。限制候选尝试
次数，禁止逐帧执行无界布局。

## 6. 响应式工作区

- 各路由导航使用相同轨道尺寸；选中指示和连接状态不推动 tab。连接状态不能只用
  颜色表达。
- 筛选器按完整控件换行，或把次要选项放入可访问的展开区域。不能为维持单行而
  挤压名称、数值或触控区域。
- 图例保留分组标题及符号／文字配对，按完整条目换行。短屏提供带文字的图例展开
  入口，避免图例吞掉图区域；当前路径与活跃状态的含义仍须可查。
- 按可用视口空间计算图高度，考虑动态浏览器工具栏和安全区。剩余不足 240 CSS px
  时先收起次要区域；仍受限时允许页面滚动到可用的图区域，不能裁掉控件或把图压成
  一条窄带。
- 桌面 inspector 使用侧栏，移动端使用底部面板。预留遮挡区域，确保关闭和操作
  可达，处理屏幕键盘。若查看选中对象需要移动视口，提供明确的聚焦操作。
- History／Devices 行中的身份与状态、流量元数据分开。窄屏先把元数据移到预留的
  第二行，不能允许重叠。空白、加载和错误状态保持相同的工作区结构。

## 7. 验收约束

以下是目标回归矩阵。实现相应规则时须补充用例和浏览器覆盖，不代表当前测试套件
已经包含全部情况。

| 维度 | 必测情况 |
| --- | --- |
| CSS 视口 | 320 × 568、390 × 844、430 × 932、844 × 390、1440 × 900 |
| 浏览器 | 桌面／移动 Chromium；涉及 Safari 差异的改动增加 WebKit；明确记录真机 iOS 验证结果或未验证 |
| 数据 | 空图、双节点、类似截图的六设备共享 DERP 聚集、长名称及重复前缀、中日韩文字、多中继、部分／匿名／冲突身份、时间偏差、250 节点／1,000 边规模夹具 |
| 动态变化 | 速率／单位长度变化、active/recent 切换、中继切换、字体延迟加载、重连、冷启动／缓存恢复、搜索、筛选、尺寸变化、拖动、Fit、Relayout |
| 交互 | 鼠标、键盘、触控、inspector 开关、输入键盘、浏览器 200% 缩放、图缩放跨越细节模式的两个阈值 |

使用确定性的合成夹具，并明确标注为合成数据。复现截图中的几何关系和长中继标签，
无需私有设备名或真实 Tailnet。视口／数据用例覆盖首次加载与缓存恢复；动态变化
覆盖小型中继夹具与规模夹具；交互用例至少覆盖 390 × 844 和 1440 × 900。

几何断言使用渲染后的屏幕边界，覆盖实体、标签、徽标、控件及带描边路径。Canvas
内部元素需要渲染器诊断数据，外层 DOM 矩形无法证明内部没有重叠。只排除前文规定
的自身对象有意重叠。断言间距、裁切、独立点击区域，以及被动更新时真实节点位置和
视口稳定。省略标签时验证声明的细节模式及选择后的信息恢复。仅检查节点数量或
控制台无错误不构成排版验收。

检查并附上桌面／移动端的默认、选中及密集状态截图，记录视口、缩放、夹具、浏览器
与细节模式。UI PR 标记 ready 前，执行标准 dev container 的 `make check`，以及
相关新增几何和交互用例。截图不能单独证明触控和键盘可用，Chromium 移动模拟也
不能证明 iOS Safari 表现正确。

## 8. 实现状态

Issue #179 基于 af9c331，包含已合入的连线避障修复和 Devices 页面。首次截图分析
使用了较旧的协调目录；本次实现保留较新的行为。

第一阶段加入屏幕几何、文本测量、八个稳定名称锚点、自适应 DERP 胶囊、有界展示
调度、细节模式滞回、对象列表选择和可移动节点完整区域分离。既有避障逻辑改用
自适应曲线细分。Fit 预留控件和状态区域，在三轮校正期间固定虚拟节点，且不移动
真实节点。短屏允许滚动到 420px 的图区域，图例按实际高度占位。

完整几何诊断仅在 VITE_LAYOUT_DIAGNOSTICS=1 时编译。合成布局用例独立检查实际
标签／实体重叠和裁切。Chromium 专项检查已通过；完整 make check、规模、全站响应式
改造及 WebKit 仍由 active plan 跟踪。未验证真机 iOS。8ms 调度器在工作项之间让出
主线程；既有有界连线避障调用仍为原子操作，需通过规模验证。

第二阶段已实现共享 44px 触控区域、窄屏身份／元数据分行、完整控件换行、安全区
内边距及可视视口键盘偏移；320／390px 工作区独立检查和既有路由测试已通过。
