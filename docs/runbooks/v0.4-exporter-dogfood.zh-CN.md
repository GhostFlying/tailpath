# v0.4 嵌入式 exporter dogfood

[English version](v0.4-exporter-dogfood.md)

本手册使用真实 Tailscale 控制面和数据面验证三个嵌入式 tsnet observer 与一个
独立 reporter identity。observer 仍然只读取被动 runtime status；只有显式启用的
示例 workload 会产生普通 HTTP 流量。

## 安全边界

- 使用独立 Tailnet，以及能创建六个临时节点的 reusable **ephemeral** auth key；
  它的 tag/Grants 只需允许这些节点互访 TCP 8080 和 18088。
- 禁止 `tailscale ping`、抓包、preferences 修改和主动 path API，也不能降低
  Tailpath WhoIs 鉴权。
- `udp derp` 只修改 exporter 容器的临时 network namespace：保留 DNS UDP，
  阻止其他 UDP，直到执行 `udp restore`。
- 原始 topology、History、identity、endpoint、Tailnet 名称和 credential 只能留在
  `/tmp` 下 mode-0700 evidence 目录。仓库只允许保存人工复核后的 sanitizer 输出。
- helper 只接受 `edge-<40 位 main SHA>`，不允许本地构建或 mutable `edge`。

## 不可变候选

先合入完整 v0.4 stack，并选择 `Publish immutable edge image` 成功的 `main` CI：

```sh
export CANDIDATE_SHA=<40-character-main-sha>
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
export TAILPATH_EXPORTER_DOGFOOD_PREFIX=tailpath-exporter-dogfood
export TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR="$(mktemp -d /tmp/tailpath-exporter-dogfood-secret.XXXXXX)"
chmod 0700 "$TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR"
export TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE="$TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR/authkey"
install -m 600 /dev/null "$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
IFS= read -r -s AUTH_KEY
printf '%s\n' "$AUTH_KEY" >"$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
unset AUTH_KEY
chmod 0444 "$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
scripts/exporter-dogfood.sh up
scripts/exporter-dogfood.sh status
```

`up` 拉取 full-SHA image，等待 server/exporter/inspector 以及恰好三个 application
observer 正常，然后立即清空 key 文件。另行记录 CI URL 和 OCI index digest。
若相同 Compose project 已存在 container、volume 或 network，`up` 会拒绝启动；必须先
执行 `down` 并检查上一轮 evidence，避免旧 state 污染新候选。

## Direct、DERP 与恢复

runtime A 每两秒通过自己的 tsnet stack 从 runtime B 下载一次 8 MiB stream，每次
显式新建普通 HTTP connection：

```sh
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture direct

scripts/exporter-dogfood.sh udp derp
scripts/exporter-dogfood.sh wait-path derp
scripts/exporter-dogfood.sh capture derp

scripts/exporter-dogfood.sh udp restore
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture restored
```

sanitized 结果必须显示三个 reporting runtimes、reporter 没有被当成 observer、同一
A-B edge 为 active、双向流量为正，History 同时包含 `direct` 和 `derp`。UI 默认
仍隐藏 Tailpath control traffic。失败时先恢复 UDP，不能改 host firewall 或
Tailnet preferences。

## Server outage 与 no-catch-up

```sh
scripts/exporter-dogfood.sh server-outage
```

helper 会停止 server，确认 exporter 进入 degraded，保持 30 秒 outage，再启动 server
并确认恰好一次 recovery。两个 raw 文件里的私有 edge ID 必须相同，History 不能丢失。设 outage 前 sanitized
速率为 `B`、恢复后的速率为 `A`，要求 `A <= max(4*B, 16777216)`；超过即视为
catch-up blocker，不能直接忽略。私有 15 分钟 History 在 outage 前后的字节增量也不得
超过 64 MiB。exporter 日志不得含 endpoint 或 credential。

## Withdrawal 与进程重启

```sh
scripts/exporter-dogfood.sh lifecycle
scripts/exporter-dogfood.sh restart-exporter
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture exporter-restarted
scripts/exporter-dogfood.sh assert-continuity restored exporter-restarted
```

`lifecycle` 从 named volume 重建 exporter 进程，然后依次要求三个 reporting、
`2 reporting + 1 stale`、再次三个 reporting，并生成 `withdrawn` / `restarted`
sanitized evidence。runtime C 的私有 stable identity 必须不变。额外 exporter
restart 后也要保持三个 runtimes、同一业务 edge、History 和 no-catch-up 上限。

## Evidence 与清理

ledger 只能包含 candidate SHA、workflow、digest、image version、通用平台版本、
pass/fail 和 sanitized JSON 字段。禁止保留 raw JSON、hostname、canonical ID、
Tailnet 名称、endpoint、auth key、DERP region 名称或原始日志内容。

```sh
scripts/exporter-dogfood.sh down
scripts/exporter-dogfood.sh purge-raw
```

再次人工检查剩余文件；closeout PR 接受后删除整个私有目录，并在控制面 revoke
reusable key。Tag 和 Release 始终由人执行。
