# v0.4 embedded exporter dogfood

[Chinese version](v0.4-exporter-dogfood.zh-CN.md)

This runbook qualifies three embedded tsnet observers and one dedicated
reporter against real Tailscale control-plane and data-plane state. It remains
passive: the observer reads runtime status; an explicit opt-in application
workload generates ordinary HTTP traffic.

## Safety boundary

- Use a dedicated Tailnet and a reusable **ephemeral** auth key that can enroll
  six disposable nodes. Its tag/Grants must allow these nodes to reach each
  other on TCP 8080 and 18088.
- Never run `tailscale ping`, packet capture, preference mutation, or an active
  path API. Do not weaken Tailpath authorization.
- `udp derp` modifies only the exporter container's disposable network
  namespace. It permits DNS UDP and rejects other UDP until `udp restore`.
- Raw topology, History, identities, endpoints, Tailnet names, and credentials
  stay in the mode-0700 evidence directory under `/tmp`. Commit only sanitizer
  output after manually checking it.
- The helper accepts only `edge-<40-character-main-sha>`. It never builds a
  local candidate or accepts mutable `edge`.

## Immutable candidate

Merge the complete v0.4 stack first. Select a successful `main` CI run whose
`Publish immutable edge image` job completed, then record its workflow URL:

```sh
export CANDIDATE_SHA=<40-character-main-sha>
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
export TAILPATH_EXPORTER_DOGFOOD_PREFIX=tailpath-exporter-dogfood
export TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR="$(mktemp -d /tmp/tailpath-exporter-dogfood-secret.XXXXXX)"
chmod 0700 "$TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR"
export TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE="$TAILPATH_EXPORTER_DOGFOOD_SECRET_DIR/authkey"
install -m 600 /dev/null "$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
```

Stage the key without putting it in shell history, then start the project:

```sh
IFS= read -r -s AUTH_KEY
printf '%s\n' "$AUTH_KEY" >"$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
unset AUTH_KEY
chmod 0444 "$TAILPATH_EXPORTER_DOGFOOD_AUTHKEY_FILE"
scripts/exporter-dogfood.sh up
scripts/exporter-dogfood.sh status
```

`up` pulls the immutable image, starts server/exporter/inspector identities,
waits for exactly three application observers, and zeroes the auth-key file.
The 0700 host directory protects the 0444 source file; the Docker daemon mounts
that single file where the image's nonroot user can read it.
Record the full OCI index digest separately with `docker buildx imagetools
inspect`. The private evidence directory is printed once and persisted in the
mode-0600 runtime file.
It also fails closed if the Compose project already owns any container, volume,
or network; use `down` and inspect the previous evidence before starting a new
candidate so persisted state cannot contaminate qualification.
The mode-0600 runtime file records the exact Compose project. Later commands
reuse that value, reject an explicit mismatch, and recheck that the evidence
directory is still a direct `/tmp` child with exact mode 0700 before reading or
writing private captures.

## Direct baseline

The example continuously downloads an 8 MiB stream from runtime B through
runtime A, using a new ordinary HTTP connection every two seconds:

```sh
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture direct
```

The sanitized result must show three reporting runtimes, no reporter observer,
an active Direct business edge, positive traffic in both directions, and
non-empty 15-minute History. In the UI, Tailpath control traffic remains hidden
by default and the visible business edge matches the sanitized result.

## DERP and restoration

```sh
scripts/exporter-dogfood.sh udp derp
scripts/exporter-dogfood.sh wait-path derp
scripts/exporter-dogfood.sh capture derp

scripts/exporter-dogfood.sh udp restore
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture restored
```

The same canonical A-B edge must transition `direct -> derp -> direct` without
an active probe. The restored History summary must contain both `direct` and
`derp`. Restore UDP immediately if convergence fails; do not change host
firewall or Tailnet preferences.

## Server outage

Stop only the immutable server, require the exporter to enter degraded state,
keep it unavailable for 30 seconds while the workload continues, then require
one recovery transition and a fresh normal sample:

```sh
scripts/exporter-dogfood.sh server-outage
```

The edge ID remains private but must be identical in the two raw files. History
must remain non-empty. Let `B` be the sanitized pre-outage bytes/s and `A` the
post-recovery bytes/s. Require `A <= max(4*B, 16777216)`; a larger value is a
catch-up blocker and must be investigated rather than discarded. The private
15-minute History sums only buckets beginning at or after the pre-outage
capture's `to`, excluding old traffic realigned by the sliding window. The
fixed 30-second outage keeps a 10-second boundary bucket from containing both
pre-outage and recovered traffic. Added bytes must stay at or below 64 MiB. The
helper requires exactly one new degraded/recovered transport episode;
also inspect the logs for raw endpoint or credential text.

## Withdrawal and process restart

The lifecycle command recreates the exporter process from its named volume,
then enables one timed runtime-C withdrawal/restart:

```sh
scripts/exporter-dogfood.sh lifecycle
```

It requires three reporting runtimes after process startup, then `2 reporting +
1 stale`, and finally three reporting again. It captures sanitized `withdrawn`
and `restarted` evidence. Runtime C must retain the same private stable identity;
the A-B workload must not spike because C had no business traffic.

Run one additional reporter/process restart without lifecycle mutation:

```sh
scripts/exporter-dogfood.sh restart-exporter
scripts/exporter-dogfood.sh wait-path direct
scripts/exporter-dogfood.sh capture exporter-restarted
scripts/exporter-dogfood.sh assert-continuity restored exporter-restarted
```

Require three reporting runtimes, stable private runtime identities, one
business edge, preserved History, and the same no-catch-up bound.

## Evidence and cleanup

The retained ledger may contain only candidate SHA/workflow/digest, image-
reported version, generic platform versions, pass/fail values, and the sanitized
JSON fields. It must not contain raw JSON, hostnames, canonical IDs, Tailnet
names, endpoints, auth keys, DERP region names, or log payloads.

After copying only safe summaries into the ledger:

```sh
scripts/exporter-dogfood.sh down
scripts/exporter-dogfood.sh purge-raw
```

Inspect the remaining files once more, then delete the private directory when
the closeout PR is accepted. Revoke the reusable key in the control plane. Tags
and releases remain human-only.
