# v0.2 release gates and dogfood

[中文版](v0.2-release-gates.zh-CN.md)

This runbook is the evidence contract for `v0.2.0-alpha.1` and `v0.2.0`.
Tags and GitHub Releases are created by a human release owner. Tailpath remains
passive: dogfood uses ordinary application traffic and never runs a path probe.

## Gate record

Create one private evidence directory outside the repository and record these
values before testing:

| Field | Required value |
| --- | --- |
| Candidate tag and commit | `v0.2.0-alpha.1`, full commit SHA |
| Release workflow | successful run URL |
| Performance workflow | successful `V0.2 release gate` run URL |
| Container | immutable `ghcr.io/ghostflying/tailpath@sha256:...` |
| Archives | all six archive names and SHA-256 values |
| Checksums | successful `sha256sum -c checksums.txt` output |
| Linux environment | distribution, architecture, tailscaled version |
| macOS environment | hardware, macOS version, Tailscale version |

Do not rebuild, retag, or substitute a branch image after this record exists.
A changed commit, digest, or checksum starts a new candidate.

## Automated gates

Run the manual workflow against the candidate commit. Its artifact must contain
`gate.json`, load and API latency data, RSS and cgroup samples, container state
and logs, restart smoke output, seven-day database output, browser JSON, and
desktop/mobile screenshots. Accept only when:

- 125 reports/s runs for 10 minutes with no loss, rejection, 500, OOM, or
  restart; ingest p95 is at most 100 ms and p99 at most 250 ms.
- Process RSS is at most 384 MiB under the 2 CPU / 512 MiB container limit.
- Topology p95 is at most 250 ms and history list/detail p95 at most 500 ms.
- The seven-day synthetic database is at most 2 GiB.
- The desktop 250-node/1,000-edge graph is ready within five seconds and an SSE
  edge-only update is visible within 500 ms without layout or viewport change.
- The candidate commit passes hosted CI and final `make check`.

The same path has a short local diagnostic mode; it is not release evidence:

```sh
TAILPATH_PERF_DURATION=10s \
TAILPATH_PERF_API_SAMPLES=5 \
TAILPATH_PERF_OUTPUT_DIR=/tmp/tailpath-perf-short \
./scripts/perf-gate.sh
```

## Isolated Linux container smoke

Use the existing [container smoke runbook](v0.1-container-smoke.md), but pin the
recorded alpha image digest. Supply a reusable ephemeral auth key through the
documented mode-0600 file; never put it in Git, shell history, Compose YAML, or
evidence. The harness zeroes the file after enrollment. Always arrange cleanup:

```sh
trap 'scripts/smoke.sh udp restore a b 2>/dev/null || true; scripts/smoke.sh down 2>/dev/null || true' EXIT
scripts/smoke.sh up
scripts/smoke.sh traffic a b
scripts/smoke.sh udp block a b
scripts/smoke.sh traffic a b
scripts/smoke.sh udp restore a b
scripts/smoke.sh traffic a b
scripts/smoke.sh restart-server
scripts/smoke.sh collector restart b
```

Record sanitized Live and History screenshots and API assertions. The same
logical edge must show Direct, DERP with a real region, then Direct; restart and
collector resync must preserve canonical identity and history. Stop one
collector for longer than two heartbeat intervals and verify stale provenance
does not remain active. Verify History list/detail in `15m` and `1h` windows.

The current smoke helper builds the checked-out source. Before alpha dogfood,
the human operator must alter its image source to the recorded digest or run an
equivalent isolated Compose overlay. A locally rebuilt image does not satisfy
the immutable-artifact gate.

## Native Linux collector

On a real Linux Tailscale node, verify the archive checksum, extract it, and
follow [native deployment](../deployment.md#native-collector-archives):

1. Run `./tailpath collector --check`; save the sanitized JSON and confirm it
   reports self, OS, and peers without contacting the Tailpath server.
2. Install with `sudo ./install.sh --server-url <tailnet-server-url>` and verify
   the hardened systemd service is active.
3. Generate ordinary application traffic and verify Direct traffic, direction,
   rate, provenance, and History.
4. Stop the server long enough to observe one collector failure transition,
   restart it, and verify one recovery plus a full hello/resync without replayed
   offline traffic.
5. Edit a harmless config comment, reinstall, and verify the config is kept.
   Run default uninstall and verify config remains; reinstall and verify it is
   reused. Use `--purge` only during final cleanup.

## Native arm64 macOS collector

Run this gate on real arm64 hardware as the logged-in GUI user, never through
`sudo` or a headless account. Verify the archive checksum, then:

1. With the Tailscale GUI connected, run `./tailpath collector --check` and
   confirm access through the GUI safesocket.
2. Install with `./install.sh --server-url <tailnet-server-url>` and inspect
   `launchctl print "gui/$(id -u)/com.tailpath.collector"`.
3. Log out and back in, then verify the LaunchAgent starts without a terminal.
4. Generate ordinary Direct application traffic and verify the Live graph and
   History. Do not use `tailscale ping`.
5. Stop and restore the server; verify bounded logs, backoff, a single recovery,
   and full resync without offline traffic replay.
6. Reinstall and default-uninstall while proving config and logs are preserved;
   purge only during final cleanup.

Attach sanitized command output, timestamps, logs, and screenshots. macOS
remains alpha-pending-validation until this entire section passes. Windows
remains an unverified preview; hosted build, PowerShell parsing, archive layout,
and installer fixtures are its only v0.2 gates.

## Review and decision

After alpha dogfood, an independent reviewer inspects the complete stack and
evidence read-only. Every blocker needs a focused regression test and the
affected gate must be rerun without relaxing thresholds. The human release
owner may create `v0.2.0` only when the decision record links the exact commit,
image digest, checksums, automated gate, Linux and Mac evidence, review, blocker
resolutions, and final `make check`.

No supported backup or restore contract exists in v0.2.
