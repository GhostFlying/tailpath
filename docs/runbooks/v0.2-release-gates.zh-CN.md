# v0.2 发布门禁与 dogfood

[English version](v0.2-release-gates.md)

本文定义 `v0.2.0-alpha.1` 和 `v0.2.0` 的证据合同。Tag 和 GitHub Release 只由
人工 release owner 创建。Tailpath 始终保持被动：dogfood 只产生普通应用流量，
不得执行 path probe。

## 候选产物记录

测试前在仓库外创建私有 evidence 目录，记录：

| 字段 | 必需内容 |
| --- | --- |
| Candidate tag / commit | `v0.2.0-alpha.1`、完整 commit SHA |
| Release workflow | 成功 run URL |
| Performance workflow | 成功的 `V0.2 release gate` run URL |
| Container | 不可变 `ghcr.io/ghostflying/tailpath@sha256:...` |
| Archives | 六个 archive 的名称和 SHA-256 |
| Checksums | `sha256sum -c checksums.txt` 成功输出 |
| Linux 环境 | distribution、architecture、tailscaled 版本 |
| macOS 环境 | 硬件、macOS、Tailscale 版本 |

记录建立后不得 rebuild、retag 或替换为 branch image；commit、digest 或 checksum
任一变化都必须建立新的 candidate。

## 自动门禁

对 candidate commit 运行手动 workflow。Artifact 必须包含 `gate.json`、load/API
延迟、RSS/cgroup samples、container state/log、restart smoke、七天数据库结果、
browser JSON 和桌面/移动截图，并满足：

- 125 reports/s 持续 10 分钟，无丢失、拒绝、500、OOM 或 restart；ingest p95
  不超过 100 ms，p99 不超过 250 ms。
- 2 CPU / 512 MiB 限制下 process RSS 不超过 384 MiB。
- topology p95 不超过 250 ms，history list/detail p95 不超过 500 ms。
- 七天 synthetic database 不超过 2 GiB。
- 桌面 250 nodes / 1,000 edges 在五秒内 ready；edge-only SSE 更新在 500 ms
  内可见，且不改变 layout 和 viewport。
- candidate commit 的 hosted CI 与最终 `make check` 全部通过。

本地可运行相同路径的短诊断，但它不属于 release evidence：

```sh
TAILPATH_PERF_DURATION=10s \
TAILPATH_PERF_API_SAMPLES=5 \
TAILPATH_PERF_OUTPUT_DIR=/tmp/tailpath-perf-short \
./scripts/perf-gate.sh
```

## 隔离 Linux container smoke

沿用 [container smoke 手册](v0.1-container-smoke.zh-CN.md)，但必须 pin 已记录的
alpha image digest。Reusable ephemeral auth key 只通过 mode-0600 文件提供，不得
进入 Git、shell history、Compose YAML 或 evidence。Harness enrollment 后会清零
文件。必须预先安排 rollback/cleanup：

```sh
trap 'scripts/smoke.sh udp restore a b 2>/dev/null || true; scripts/smoke.sh down 2>/dev/null || true' EXIT
scripts/smoke.sh up
scripts/smoke.sh traffic a b
scripts/smoke.sh udp block a b
scripts/smoke.sh traffic a b
scripts/smoke.sh udp restore a b
scripts/smoke.sh traffic a b
scripts/smoke.sh restart-server
scripts/smoke.sh collector restart b
```

保存脱敏后的 Live/History 截图和 API 断言。同一 logical edge 必须依次显示
Direct、带真实 region 的 DERP、Direct；server restart 与 collector resync 后
canonical identity 和 history 必须保留。停止一个 collector 超过两倍 heartbeat，
验证 stale provenance 不再 active；验证 `15m`、`1h` 的 History list/detail。

当前 smoke helper 会构建 checkout source。正式 alpha dogfood 前，人工 operator
必须把 image source 改为已记录 digest，或使用等价的隔离 Compose overlay。Local
rebuild 不满足 immutable-artifact gate。

## 原生 Linux collector

在真实 Linux Tailscale 节点校验 archive checksum、解压，并参考
[原生部署](../deployment.zh-CN.md#原生-collector-archives)：

1. 执行 `./tailpath collector --check`，保存脱敏 JSON；确认只报告 self、OS、peer，
   不连接 Tailpath server。
2. 使用 `sudo ./install.sh --server-url <tailnet-server-url>` 安装，确认 hardened
   systemd service active。
3. 产生普通应用流量，验证 Direct、方向、速率、provenance 和 History。
4. 停止 server，观察一次 collector failure transition；恢复后验证只输出一次
   recovery，并发送完整 hello/resync，不重放离线流量。
5. 在配置里加入无害注释后 reinstall，确认配置保留；默认 uninstall 仍保留配置，
   reinstall 会复用它。只在最终清理使用 `--purge`。

## 原生 arm64 macOS collector

必须在真实 arm64 Mac 上由当前登录 GUI 用户执行，不能使用 `sudo` 或 headless
account。校验 archive checksum 后：

1. Tailscale GUI 已连接时执行 `./tailpath collector --check`，确认通过 GUI
   safesocket 访问 LocalAPI。
2. 执行 `./install.sh --server-url <tailnet-server-url>`，检查
   `launchctl print "gui/$(id -u)/com.tailpath.collector"`。
3. 注销并重新登录，确认 LaunchAgent 不依赖 terminal 自动启动。
4. 产生普通 Direct 应用流量并验证 Live/History；不得使用 `tailscale ping`。
5. 停止并恢复 server，验证有界日志、backoff、单次 recovery 和完整 resync，且不
   重放离线流量。
6. Reinstall 和默认 uninstall 必须保留 config/log；只在最终清理 purge。

附上脱敏 command output、timestamp、log 和截图。整段通过之前 macOS 保持
alpha-pending-validation。Windows 保持未经验证的 preview；其 v0.2 gate 只有 hosted
build、PowerShell parse、archive layout 和 installer fixture。

## Review 与发布决定

Alpha dogfood 后，由独立 reviewer 只读审查完整 stack 和 evidence。每个 blocker
必须有聚焦 regression test，相关门禁必须在不放宽 threshold 的前提下重跑。只有
decision record 链接了精确 commit、image digest、checksums、自动门禁、Linux/Mac
证据、独立 review、blocker 修复和最终 `make check`，人工 release owner 才能创建
`v0.2.0`。

v0.2 不提供受支持的 backup/restore contract。
