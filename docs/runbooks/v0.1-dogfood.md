# v0.1 passive dogfood runbook

[中文版](v0.1-dogfood.zh-CN.md)

Status: optional cross-host operational follow-up, awaiting operator-selected
hosts. The [real-Tailnet container smoke](v0.1-container-smoke.md) now covers the
required Direct/DERP path transition with a controlled disposable-network fault.

## Purpose

This runbook exercises packaging, native and Compose collectors, and path
behavior across operator-selected hosts. The container smoke already validates
real LocalAPI, tsnet, Direct and DERP traffic, provenance, lifecycle, and path
transition behavior on one Docker host. This optional run does not try to prove
complete Tailnet inventory.

Tailpath must remain passive throughout the run:

- Never run `tailscale ping`, LocalAPI Ping, packet capture, route probes, or a
  Tailscale preference or policy mutation as part of Tailpath.
- `tailscale ip` and `tailscale status --json` are allowed because they read
  local runtime state.
- Test traffic is an explicit HTTP file transfer between the dogfood nodes. It
  exercises a real application connection rather than a path-discovery probe.
- A DERP case uses an operator-provided constrained network. This runbook does
  not install firewall rules or change node networking to force DERP.

## Approval worksheet

Fill this in before execution. Do not record auth keys or public endpoints.

| Item | Approved value |
| --- | --- |
| Immutable Tailpath commit | |
| `S`, server Docker host | |
| `A`, Linux native-collector node | |
| `B`, Linux Compose-collector node | |
| Dedicated tsnet hostname | `tailpath-dogfood` unless overridden |
| Ordinary HTTP test port allowed by Tailnet policy | `18088` unless overridden |
| Existing network condition that keeps `A` to `B` on DERP, if DF-06 runs | |
| Names or screenshots safe to attach to the public PR | |

Use a new Compose project, tsnet hostname, and volume. Never reuse a production
Tailpath database or tsnet state. `A` and `B` must be controlled, trusted
reporters in the same Tailnet. Their runtime peer views may differ because
Tailscale policy can limit visibility; that is valid input, not a test failure.

## Artifact preparation

Run from a clean checkout of the approved commit on `S`:

```sh
test -z "$(git status --porcelain)"
export DOGFOOD_SHA="$(git rev-parse HEAD)"
export TAILPATH_VERSION="dogfood-$(git rev-parse --short=12 HEAD)"
export DOGFOOD_IMAGE="ghcr.io/ghostflying/tailpath:${TAILPATH_VERSION}"
export DOGFOOD_PROJECT="tailpath-dogfood"
export TAILPATH_HOSTNAME="tailpath-dogfood"
umask 077
export DOGFOOD_EVIDENCE="$(mktemp -d /tmp/tailpath-dogfood-evidence.XXXXXX)"

docker compose -p "$DOGFOOD_PROJECT" build server
docker run --rm "$DOGFOOD_IMAGE" version | tee "$DOGFOOD_EVIDENCE/version.txt"
test "$(docker run --rm "$DOGFOOD_IMAGE" version)" = "$TAILPATH_VERSION"
docker image inspect "$DOGFOOD_IMAGE" --format '{{.Id}}' \
  | tee "$DOGFOOD_EVIDENCE/image-id.txt"
git show -s --format='%H %cI %s' \
  | tee "$DOGFOOD_EVIDENCE/commit.txt"
```

Extract the exact Linux binary from this image for `A`. Transfer it and the
image to `A` and `B` through the operator-approved channel; record checksums
before and after transfer.

```sh
artifact_container="$(docker create "$DOGFOOD_IMAGE" version)"
docker cp "$artifact_container:/usr/local/bin/tailpath" \
  "$DOGFOOD_EVIDENCE/tailpath-linux"
docker rm "$artifact_container"
chmod 0755 "$DOGFOOD_EVIDENCE/tailpath-linux"
sha256sum "$DOGFOOD_EVIDENCE/tailpath-linux" \
  | tee "$DOGFOOD_EVIDENCE/tailpath-linux.sha256"
docker save "$DOGFOOD_IMAGE" \
  | gzip > "$DOGFOOD_EVIDENCE/tailpath-image.tar.gz"
sha256sum "$DOGFOOD_EVIDENCE/tailpath-image.tar.gz" \
  | tee "$DOGFOOD_EVIDENCE/tailpath-image.tar.gz.sha256"
```

Do not publish a dogfood tag or release. The commit, binary checksum, image ID,
and reported `version` are the artifact identity.

## Preflight

On `A` and `B`, record local status without probing peers:

```sh
date -u +%FT%TZ
tailscale version
tailscale ip -4
tailscale status --json | jq '{BackendState,Self,PeerCount:(.Peer|length)}'
```

Confirm all of the following before starting:

- `A` and `B` have synchronized clocks and no unexpected clock warning.
- Tailnet policy already allows `A` and `B` to reach the dedicated Tailpath
  node on TCP 8080 and each other on the approved HTTP test port.
- `S` can persist the isolated Compose volume.
- `B` has the read-only tailscaled socket at the configured path.
- No existing service or test uses the chosen hostname, Compose project, or
  HTTP port.
- If optional DF-06 will run, its DERP environment is known in advance. If it
  cannot be provided, skip that case rather than forcing it with an active
  probe.

## Start the server

Provision a one-use, scoped tsnet auth key through the operator's secret
manager. Stage it in a private temporary directory, enroll the server, then
zero the file. Persistent tsnet state keeps the enrolled identity while the
empty file remains available to future Compose recreations.

```sh
export DOGFOOD_SECRET_DIR="$(mktemp -d /tmp/tailpath-dogfood-secret.XXXXXX)"
chmod 0700 "$DOGFOOD_SECRET_DIR"
export TAILPATH_AUTHKEY_FILE="$DOGFOOD_SECRET_DIR/tailscale-authkey"
read -r -s -p 'One-use tsnet auth key: ' tailpath_authkey
printf '\n'
printf '%s\n' "$tailpath_authkey" > "$TAILPATH_AUTHKEY_FILE"
unset tailpath_authkey
chmod 0444 "$TAILPATH_AUTHKEY_FILE"
export TAILPATH_VERSION TAILPATH_HOSTNAME TAILPATH_AUTHKEY_FILE
docker compose -p "$DOGFOOD_PROJECT" up -d server

wait_for_server() {
  until docker compose -p "$DOGFOOD_PROJECT" ps --format json \
    | jq -e '.[] | select(.Service == "server" and .Health == "healthy")' >/dev/null; do
    sleep 2
  done
}
wait_for_server

chmod u+w "$TAILPATH_AUTHKEY_FILE"
: > "$TAILPATH_AUTHKEY_FILE"
chmod 0444 "$TAILPATH_AUTHKEY_FILE"
docker compose -p "$DOGFOOD_PROJECT" down
docker compose -p "$DOGFOOD_PROJECT" up -d server
wait_for_server
docker compose -p "$DOGFOOD_PROJECT" ps
docker compose -p "$DOGFOOD_PROJECT" logs --no-color server \
  > "$DOGFOOD_EVIDENCE/server-start.log"
```

Verify that Compose publishes no bridge or host port. The application listener
must exist only inside tsnet:

```sh
server_container="$(docker compose -p "$DOGFOOD_PROJECT" ps -q server)"
docker inspect "$server_container" \
  | jq -e '.[0].HostConfig.PortBindings | . == null or length == 0'
docker inspect "$server_container" \
  | jq -e '.[0].Config.Env | map(select(startswith("TS_AUTHKEY="))) == ["TS_AUTHKEY=file:/run/secrets/tailscale-authkey"]'
docker inspect "$server_container" \
  | jq -e '.[0].Mounts | ([.[] | select(.Destination == "/var/lib/tailpath" and .Type == "volume")] | length == 1) and ([.[] | select(.Destination == "/var/lib/tailpath/tsnet")] | length == 0)'
test ! -s "$TAILPATH_AUTHKEY_FILE"
```

From a Tailnet node, open `http://tailpath-dogfood:8080/` and confirm the UI
loads. Also confirm an authenticated topology request succeeds:

```sh
curl --fail --silent --show-error \
  http://tailpath-dogfood:8080/api/v1/topology | jq '.generatedAt'
```

## Start collectors

Install the verified binary on `A` and run it as a native transient service:

```sh
sudo install -m 0755 ./tailpath-linux /usr/local/bin/tailpath-dogfood
sudo systemd-run --unit=tailpath-dogfood-collector-a \
  --property=Restart=on-failure \
  /usr/local/bin/tailpath-dogfood collector \
  --server=http://tailpath-dogfood:8080 \
  --socket=/var/run/tailscale/tailscaled.sock
```

Load the verified image on `B`, use the checkout from the same commit for
`compose.yaml`, and start only the host-network collector profile:

```sh
gzip -dc ./tailpath-image.tar.gz | docker load
export TAILPATH_VERSION="dogfood-<approved-short-sha>"
export TAILPATH_SERVER_URL="http://tailpath-dogfood:8080"
docker compose -p tailpath-dogfood-b --profile collector up -d collector
docker compose -p tailpath-dogfood-b ps
```

Allow at least one heartbeat interval plus ten seconds. The UI must show both
observers online but no `A` to Tailpath or `B` to Tailpath edge. Collector
reporting traffic is control traffic and must never become the only active
relationship.

## Evidence helper

Raw topology JSON contains canonical IDs and direct endpoints. Keep it outside
the repository and do not attach it to the public PR. The following projection
removes IDs and direct endpoints while retaining the dogfood assertions. Run
this on `A` or another approved Tailnet node, with a separate local evidence
directory if `S` itself is not in the Tailnet:

```sh
umask 077
export DOGFOOD_EVIDENCE="$(mktemp -d /tmp/tailpath-dogfood-evidence.XXXXXX)"
capture_topology() {
  label="$1"
  curl --fail --silent --show-error \
    http://tailpath-dogfood:8080/api/v1/topology \
    > "$DOGFOOD_EVIDENCE/${label}-raw.json"
  jq '(.nodes | map({key:.id,value:(.dnsName // .hostname // "unnamed")}) | from_entries) as $names
      | {generatedAt,nextChangeAt,
         nodes:[.nodes[]|{name:(.dnsName // .hostname),observable,online,clockSkewed}],
         edges:[.edges[]|{source:$names[.source],target:$names[.target],
           path:{kind:.path.kind,derpRegion:.path.derpRegion},state,
           aToBBytesPerSecond,bToABytesPerSecond,
           observationCount:(.observations|length),conflictCount:((.conflicts // [])|length)}],
         observers:[.observers[]|{hostname,online,clockSkewed,clockSkewMs}]}' \
    "$DOGFOOD_EVIDENCE/${label}-raw.json" \
    > "$DOGFOOD_EVIDENCE/${label}-sanitized.json"
}
```

Delete raw captures after the local review. Only sanitized evidence approved in
the worksheet may be attached to the public PR.

## Test sequence

### DF-01: idle control-traffic exclusion

With both collectors running and no `A` to `B` application traffic, capture the
topology after one heartbeat plus ten seconds.

Pass conditions:

- `A` and `B` are online observers.
- No edge exists solely because collectors report to Tailpath.
- A passive peer may be absent; runtime observers do not promise full Tailnet
  inventory.

### DF-02: direct traffic and provenance

On `B`, create a private temporary payload and serve it only on the local
Tailscale IPv4 address. Keep this shell open so its trap removes the payload.

```sh
umask 077
transfer_dir="$(mktemp -d /tmp/tailpath-transfer.XXXXXX)"
transfer_pid=""
cleanup_transfer() {
  test -z "$transfer_pid" || kill "$transfer_pid" 2>/dev/null || true
  rm -f "$transfer_dir/payload.bin"
  rmdir "$transfer_dir" 2>/dev/null || true
}
trap cleanup_transfer EXIT INT TERM
head -c 67108864 /dev/zero > "$transfer_dir/payload.bin"
b_ip="$(tailscale ip -4)"
python3 -m http.server 18088 --bind "$b_ip" --directory "$transfer_dir" &
transfer_pid="$!"
wait "$transfer_pid"
```

While that server is running, transfer the file from `A` at a stable rate:

```sh
curl --fail --silent --show-error --limit-rate 2M --output /dev/null \
  "http://<B_TAILSCALE_IPV4>:18088/payload.bin"
```

Pass conditions while the transfer is active:

- Exactly one logical `A` to `B` edge is active, not two directed edges.
- Its path settles on Direct in the approved direct-capable environment.
- Directional rate is nonzero in the transfer direction and broadly consistent
  with the 2 MiB/s cap. Exact byte equality is not expected because counters
  cover all peer traffic and sampling windows differ.
- Both `A` and `B` support the edge after each collector reports. Conflicting
  fresh evidence, if any, remains visible rather than being discarded.

Repeat with the temporary server on `A` and the client on `B` to exercise the
opposite traffic direction.

### DF-03: active, recent, and hidden aging

Stop application traffic without stopping collectors and do not reload the UI.
Record both the transfer-command exit and the edge's final `lastActive` value;
tailscaled counters can continue changing briefly after the process exits.

Pass conditions:

- At approximately 10 seconds after the final observed byte-counter delta, the
  active rate becomes zero and the edge is shown as recent.
- After two server heartbeat intervals, the edge disappears.
- Collector heartbeats do not extend the edge lifetime.
- The browser changes state at the deadline even when no SSE topology event is
  emitted.

Record actual timestamps. Allow five seconds of scheduling tolerance around
the configured deadlines.

### DF-04: one-sided observation

Stop the collector on `B`, wait two heartbeat intervals plus five seconds, then
repeat the `A` to `B` HTTP transfer.

Pass conditions:

- The edge is still visible from `A`'s observation.
- The expired `B` provenance is absent; observation count is one.
- `B` is not presented as an online observer.

Restart `B`'s collector, repeat traffic, and confirm provenance returns without
creating a second canonical `B` node.

### DF-05: server restart and SSE recovery

Generate traffic, keep the UI open, and restart only the isolated server:

```sh
docker compose -p "$DOGFOOD_PROJECT" restart server
```

Pass conditions:

- The UI returns to or remains live without a page reload. A fast restart can
  make reconnecting too brief to sample, so post-resync topology updates are
  the required reconnection proof.
- The recent logical edge, node aliases, and provenance survive the restart.
- Lifecycle aging continues from server receive timestamps; restart does not
  make stale evidence active.
- After both collectors complete hello/resync, new ordinary traffic updates the
  already-open UI.

The automated store test covers restart after raw-report retention. This short
dogfood restart validates the real image, volume, tsnet state, and browser
reconnection path; it does not replace the eight-day automated test.
Traffic while the server is unavailable or while collectors rebuild their
baselines is best effort and is not used to assert lossless outage accounting.

### DF-06: optional natural-network DERP and path transition

Place `A` and `B` in the pre-approved network condition that is already known
to keep their ordinary connection on DERP. Do not run an active path probe.
Repeat the HTTP transfer.

Pass conditions:

- The current edge changes to DERP and shows the actual region.
- The newest received traffic report wins immediately over older Direct
  evidence.
- Selecting the edge shows Direct and DERP as separate recent path events with
  provenance.
- Restoring the normal environment and transferring again changes the current
  path back to Direct.

If the connection becomes direct, record this gate as inconclusive and arrange
a genuinely constrained environment. Do not add firewall or Tailscale debug
mutations during the run merely to satisfy the expected label.

### DF-07: observer and node aging

Stop `A`'s collector and ensure there is no application traffic involving `A`.

Pass conditions:

- After two heartbeat intervals, `A` is not an online observer.
- After four heartbeat intervals without a report or traffic evidence, `A` is
  omitted from the live topology unless another fresh observation supports it.
- The UI never claims that a passive node is offline; its runtime state is
  unknown when it has no local observer.

### DF-08: exposure and clock checks

Pass conditions:

- The server has no Docker host or bridge port publication.
- Tailnet access to `/api/v1/topology` succeeds through tsnet and WhoIs.
- The dedicated Tailpath node does not produce a control-traffic edge.
- Correctly synchronized collectors show no clock warning. If a real collector
  is skewed beyond half a heartbeat interval, the UI marks that observer and
  its evidence; do not change system time solely for this test.

Wildcard-listener rejection and unauthenticated API behavior remain automated
tests. The tsnet image does not expose a wildcard host listener, so weakening
the deployment to manufacture an unauthorized request would test a different
and unsafe configuration.

## Acceptance matrix

| Gate | Required for v0.1 | Evidence |
| --- | --- | --- |
| Artifact provenance and isolated state | Yes | commit, version, checksums, image ID |
| Idle control-traffic exclusion | Yes | sanitized topology after heartbeat |
| Direct path and both directions | Yes | UI plus sanitized topology |
| One-sided observation | Yes | observation count and observer state |
| Active to recent to hidden | Yes | timestamped UI/API captures |
| Server restart and SSE reconnect | Yes | timestamps and server logs |
| Cross-host natural-network DERP transition | No; controlled smoke covers v0.1 | UI plus path history |
| Observer and node aging | Yes | timestamped topology captures |
| Peer Relay server telemetry | No, v0.3 | not run |
| tsnet/tsbridge exporter | No, v0.4 | not run |
| Full Tailnet inventory | Never required without optional directory source | not asserted |
| Eight-day soak | Follow-up | automated restart test is the v0.1 gate |

An inconclusive optional network condition does not block v0.1. Any product or
required operational discrepancy is recorded with the artifact identity,
sanitized evidence, expected result, and actual result before more changes are
made.

## Stop conditions

Stop the run and preserve local evidence if any of these occurs:

- A Tailpath command attempts an active probe, packet capture, policy change,
  or Tailscale preference mutation.
- The server is reachable through a Docker-published host or bridge port.
- An auth key, raw topology, direct endpoint, or stable node identifier appears
  in a public artifact or log attachment.
- Collector control traffic creates an edge.
- SQLite migration, runtime-state restore, or tsnet identity reuse fails.

Do not improvise around these conditions during the same run.

## Cleanup

Stop both collectors and temporary HTTP servers. On `S`, stop the isolated
server without deleting its volume so evidence remains recoverable:

```sh
sudo systemctl stop tailpath-dogfood-collector-a.service
docker compose -p tailpath-dogfood-b --profile collector down
docker compose -p "$DOGFOOD_PROJECT" down
```

Remove installed binaries, images, and the isolated Compose volume only after
the operator accepts the captured result. Never use `docker compose down -v`
as part of automatic cleanup. Revoke the one-use auth key in the control plane
if it was not already ephemeral, and verify it is absent from the recreated
container environment.

Summarize results in the Draft PR, but keep raw evidence local. Moving the PR
out of Draft and merging remain human decisions.
