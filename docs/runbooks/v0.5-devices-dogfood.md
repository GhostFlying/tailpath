# v0.5 Devices API dogfood

[Chinese version](v0.5-devices-dogfood.zh-CN.md)

This runbook qualifies the optional control-plane device directory against the
real Tailscale Devices API. It does not generate peer traffic, probe paths, or
change Tailnet policy.

## Safety boundary

- Create a dedicated OAuth client with exactly `devices:core:read`. Do not use
  an API key or grant posture, ACL, user, or write scopes.
- Qualify a successful immutable `edge-<40-character-main-sha>` image. Do not
  use a PR image, local rebuild, short SHA, or mutable `edge` tag.
- Keep the OAuth secret and raw API, topology, capability, and log captures in
  one direct `/tmp` child with exact mode 0700. Only sanitized summaries may be
  copied into the repository.
- The directory contains only devices visible to this credential. In
  particular, upstream behavior may omit shared devices; this is not a
  completeness test ([Tailscale issue #16911](https://github.com/tailscale/tailscale/issues/16911)).
- Use a separate tsnet enrollment key for the disposable server identity. The
  OAuth secret is renewable and must remain present for the whole test.

## Immutable candidate

Run from a clean checkout of the fully merged v0.5 `main` commit:

```sh
export CANDIDATE_SHA=<40-character-main-sha>
printf '%s' "$CANDIDATE_SHA" | grep -Eq '^[0-9a-f]{40}$'
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
export DEVICES_DOGFOOD_PROJECT=tailpath-v05-devices-dogfood
export DEVICES_DOGFOOD_DIR="$(mktemp -d /tmp/tailpath-v05-devices-dogfood.XXXXXX)"
chmod 0700 "$DEVICES_DOGFOOD_DIR"
install -d -m 0700 "$DEVICES_DOGFOOD_DIR/raw" "$DEVICES_DOGFOOD_DIR/safe"

export TAILPATH_AUTHKEY_FILE="$DEVICES_DOGFOOD_DIR/tsnet-authkey"
export TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE="$DEVICES_DOGFOOD_DIR/devices-oauth-secret"
install -m 0600 /dev/null "$TAILPATH_AUTHKEY_FILE"
install -m 0600 /dev/null "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
```

Validate `CANDIDATE_SHA` against the successful main workflow and record the
workflow URL and OCI index digest outside the raw captures. Enter credentials
without placing them in shell history:

```sh
IFS= read -r -s TSNET_AUTH_KEY
printf '%s\n' "$TSNET_AUTH_KEY" >"$TAILPATH_AUTHKEY_FILE"
unset TSNET_AUTH_KEY

export TAILPATH_DEVICES_OAUTH_CLIENT_ID=<client-id>
export TAILPATH_DEVICES_TAILNET=-
IFS= read -r -s DEVICES_OAUTH_SECRET
printf '%s\n' "$DEVICES_OAUTH_SECRET" >"$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
unset DEVICES_OAUTH_SECRET
chmod 0444 "$TAILPATH_AUTHKEY_FILE" "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
```

Set a private URL reachable from the operator's Tailnet identity, then pull and
start the candidate:

```sh
export DEVICES_DOGFOOD_URL=http://<private-tsnet-hostname>:8080
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml pull server
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d server
```

Define one bounded capture helper for every scenario. It keeps full responses
under `raw/` and emits only sanitizer output under `safe/`:

```sh
capture_devices() {
  scenario=$1
  expected_status=$2
  deadline=$(( $(date +%s) + 180 ))
  devices_file="$DEVICES_DOGFOOD_DIR/raw/$scenario-devices.json"
  topology_file="$DEVICES_DOGFOOD_DIR/raw/$scenario-topology.json"
  while :; do
    if curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/devices" >"$devices_file" &&
      test "$(jq -r '.sync.status' "$devices_file")" = "$expected_status"; then
      break
    fi
    test "$(date +%s)" -lt "$deadline" || return 1
    sleep 5
  done
  curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/topology" >"$topology_file"
  scripts/sanitize-devices-dogfood.sh snapshot "$scenario" "$topology_file" \
    <"$devices_file" >"$DEVICES_DOGFOOD_DIR/safe/$scenario-snapshot.json"
}
```

After enrollment succeeds, truncate only the one-use tsnet key. Do not truncate
the Devices OAuth secret:

```sh
chmod 0600 "$TAILPATH_AUTHKEY_FILE"
: >"$TAILPATH_AUTHKEY_FILE"
chmod 0444 "$TAILPATH_AUTHKEY_FILE"
```

## First sync and merge

Poll `/api/v1/devices` until `sync.status` is `healthy`, then capture the
directory and topology privately:

```sh
curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/capabilities" \
  >"$DEVICES_DOGFOOD_DIR/raw/capabilities.json"
jq -e '.features | index("device-directory") != null' \
  "$DEVICES_DOGFOOD_DIR/raw/capabilities.json"

capture_devices initial healthy
jq -e '
  .directory.deviceCount > 0 and .directory.runtimeEvidenceCount > 0 and
  .directory.directoryOnlyCount > 0 and
  .liveIsolation.directoryOnlyAbsentFromTopology and
  .liveIsolation.directoryOnlyAbsentFromEdges
' "$DEVICES_DOGFOOD_DIR/safe/initial-snapshot.json" >/dev/null
```

Require at least one runtime-enriched device, at least one directory-only
device, and both Live-isolation booleans to be true. The current Live node and
edge counts are the baseline for the remaining captures. The UI must present
control connection and runtime observation as separate dimensions.

## Restart and stale recovery

Restart the server, wait for `healthy`, and capture `restart-devices.json` and
`restart-topology.json` using the same commands. Sanitize the snapshot and
compare it with the initial response:

```sh
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml restart server
capture_devices restart healthy
scripts/sanitize-devices-dogfood.sh compare restart \
  "$DEVICES_DOGFOOD_DIR/raw/initial-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/restart-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/restart-compare.json"
```

The restart must restore the last-good directory immediately, return to
`healthy`, keep the identity-set hash stable unless the real directory changed,
and leave Live counts unchanged.

Next, replace the configured secret with a controlled invalid value and force a
new process. The valid secret remains inside the private mode-0700 directory:

```sh
mv "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE" \
  "$DEVICES_DOGFOOD_DIR/devices-oauth-secret.valid"
install -m 0600 /dev/null "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
printf '%s\n' 'controlled-invalid-secret' \
  >"$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
chmod 0444 "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d --force-recreate server
```

Wait for `stale`, capture it, and compare it with the restart baseline:

```sh
capture_devices stale stale
scripts/sanitize-devices-dogfood.sh compare stale \
  "$DEVICES_DOGFOOD_DIR/raw/restart-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/stale-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/stale-compare.json"
```

Require the fixed error category `unauthorized` or `forbidden`, identical
device count, identity-set hash, directory-authoritative content hash, and
canonical-mapping hash, plus `lastGoodPreserved=true`. Runtime evidence and
conflicts are intentionally excluded from the content hash so normal observer
refreshes cannot invalidate this check. Raw response bodies and the invalid
secret must not appear in API errors or logs.

Restore the valid secret, force-recreate the server, wait for `healthy`, and
capture/sanitize `recovered-devices.json` plus topology. Require recovery,
preserved Live isolation, and no credential text in logs:

```sh
rm "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
mv "$DEVICES_DOGFOOD_DIR/devices-oauth-secret.valid" \
  "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d --force-recreate server
capture_devices recovered healthy
```

## Token renewal

Treat `recovered-devices.json` as the private renewal baseline. Keep the same
server process and secret running for more than 65 minutes. Do not restart the
container during this interval. After at least 70 minutes, run:

```sh
capture_devices renewed healthy
scripts/sanitize-devices-dogfood.sh compare renewal \
  "$DEVICES_DOGFOOD_DIR/raw/recovered-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/renewed-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/renewal.json"
```

Require `after.status=healthy` and `successAdvancedSeconds >= 3900`. A changed
identity-set hash is acceptable only if the operator confirms that the real
credential-visible directory changed during the interval. This gate proves a
post-expiry OAuth request, not merely that cached directory state survived.

## Evidence and cleanup

The committed ledger may contain only the candidate SHA, full-SHA image tag,
image-reported version, workflow URLs, scale artifact ID and expiry, OCI digest,
generic platform versions, durations, counts, booleans, fixed error categories,
latencies, and SHA-256 identity-set/content/canonical-mapping hashes produced by
the sanitizer. It must not contain raw JSON, timestamps, device names, MagicDNS
names, hostnames, IPs, tags, NodeKeys, StableNodeIDs, canonical IDs, Tailnet
names, credentials, or log payloads.

Before copying safe summaries, scan them and review every key manually. Keep
all raw files private. Then remove the isolated deployment and private data:

```sh
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml down -v --remove-orphans
case "$DEVICES_DOGFOOD_DIR" in
  /tmp/tailpath-v05-devices-dogfood.??????) rm -rf -- "$DEVICES_DOGFOOD_DIR" ;;
  *) echo "refusing unexpected evidence path" >&2; exit 1 ;;
esac
```

Revoke the dedicated OAuth client and tsnet enrollment key after qualification.
Tags and releases remain human-only.
