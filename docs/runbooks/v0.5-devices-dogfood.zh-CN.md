# v0.5 Devices API dogfood

[English version](v0.5-devices-dogfood.md)

本手册使用真实 Tailscale Devices API 验证可选控制面设备目录。整个过程不产生 peer
流量、不探测 path，也不修改 Tailnet policy。

## 安全边界

- 创建独立 OAuth client，scope 必须严格为 `devices:core:read`；不得使用 API key，
  也不能授予 posture、ACL、user 或 write scope。
- 只验证成功发布的 `edge-<40 位 main SHA>` immutable image；禁止 PR image、本地
  rebuild、短 SHA 或 mutable `edge`。
- OAuth secret、raw Devices/topology/capability/log capture 只能放在 `/tmp` 的
  mode-0700 直接子目录；仓库只能保存 sanitized summary。
- 目录只代表该 credential 当前可见的设备。上游行为可能漏掉 shared device，dogfood
  不验证完整性（[Tailscale issue #16911](https://github.com/tailscale/tailscale/issues/16911)）。
- disposable server 使用独立 tsnet enrollment key。OAuth secret 可续期，整个测试
  期间必须保留。

## 不可变候选

从完整 v0.5 stack 已合入的干净 `main` checkout 执行：

```sh
export CANDIDATE_SHA=<40-character-main-sha>
printf '%s' "$CANDIDATE_SHA" | grep -Eq '^[0-9a-f]{40}$'
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
export DEVICES_DOGFOOD_PROJECT=tailpath-v05-devices-dogfood
export DEVICES_DOGFOOD_DIR="$(mktemp -d /tmp/tailpath-v05-devices-dogfood.XXXXXX)"
chmod 0700 "$DEVICES_DOGFOOD_DIR"
install -d -m 0700 "$DEVICES_DOGFOOD_DIR/raw" "$DEVICES_DOGFOOD_DIR/safe"
export TAILPATH_AUTHKEY_FILE="$DEVICES_DOGFOOD_DIR/tsnet-authkey"
export TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE="$DEVICES_DOGFOOD_DIR/devices-oauth-secret"
install -m 0600 /dev/null "$TAILPATH_AUTHKEY_FILE"
install -m 0600 /dev/null "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
```

核对 `CANDIDATE_SHA` 对应成功的 main workflow，并在 raw capture 外记录 workflow URL
与 OCI index digest。不要把 credential 写进 shell history：

```sh
IFS= read -r -s TSNET_AUTH_KEY
printf '%s\n' "$TSNET_AUTH_KEY" >"$TAILPATH_AUTHKEY_FILE"
unset TSNET_AUTH_KEY
export TAILPATH_DEVICES_OAUTH_CLIENT_ID=<client-id>
export TAILPATH_DEVICES_TAILNET=-
IFS= read -r -s DEVICES_OAUTH_SECRET
printf '%s\n' "$DEVICES_OAUTH_SECRET" >"$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
unset DEVICES_OAUTH_SECRET
chmod 0444 "$TAILPATH_AUTHKEY_FILE" "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
```

配置 operator Tailnet identity 可访问的私有 URL，拉取并启动候选：

```sh
export DEVICES_DOGFOOD_URL=http://<private-tsnet-hostname>:8080
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml pull server
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d server
```

为所有场景定义同一个 3 分钟 bounded capture helper。完整 response 只写入 `raw/`，
`safe/` 只接收 sanitizer 输出：

```sh
capture_devices() {
  scenario=$1
  expected_status=$2
  deadline=$(( $(date +%s) + 180 ))
  devices_file="$DEVICES_DOGFOOD_DIR/raw/$scenario-devices.json"
  topology_file="$DEVICES_DOGFOOD_DIR/raw/$scenario-topology.json"
  while :; do
    if curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/devices" >"$devices_file" &&
      test "$(jq -r '.sync.status' "$devices_file")" = "$expected_status"; then
      break
    fi
    test "$(date +%s)" -lt "$deadline" || return 1
    sleep 5
  done
  curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/topology" >"$topology_file"
  scripts/sanitize-devices-dogfood.sh snapshot "$scenario" "$topology_file" \
    <"$devices_file" >"$DEVICES_DOGFOOD_DIR/safe/$scenario-snapshot.json"
}
```

enrollment 成功后只清空一次性的 tsnet key；不能清空 Devices OAuth secret：

```sh
chmod 0600 "$TAILPATH_AUTHKEY_FILE"
: >"$TAILPATH_AUTHKEY_FILE"
chmod 0444 "$TAILPATH_AUTHKEY_FILE"
```

## 首次同步与 merge

轮询 `/api/v1/devices` 直到 `healthy`，将 Devices 与 topology response 保存到私有
`raw` 目录。先断言 capability，再生成不含设备 metadata 的 summary：

```sh
curl -fsS "$DEVICES_DOGFOOD_URL/api/v1/capabilities" \
  >"$DEVICES_DOGFOOD_DIR/raw/capabilities.json"
jq -e '.features | index("device-directory") != null' \
  "$DEVICES_DOGFOOD_DIR/raw/capabilities.json"
capture_devices initial healthy
jq -e '
  .directory.deviceCount > 0 and .directory.runtimeEvidenceCount > 0 and
  .directory.directoryOnlyCount > 0 and
  .liveIsolation.directoryOnlyAbsentFromTopology and
  .liveIsolation.directoryOnlyAbsentFromEdges
' "$DEVICES_DOGFOOD_DIR/safe/initial-snapshot.json" >/dev/null
```

必须至少有一个 runtime-enriched device、一个 directory-only device，并且两个 Live
isolation 布尔值都是 true。后续 capture 以当前 Live node/edge count 为 baseline。
UI 必须把 control connection 与 runtime observation 作为两个独立维度。

## 重启与 stale 恢复

重启 server，等待 `healthy`，按相同步骤保存 `restart-devices.json` 和 topology：

```sh
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml restart server
capture_devices restart healthy
scripts/sanitize-devices-dogfood.sh compare restart \
  "$DEVICES_DOGFOOD_DIR/raw/initial-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/restart-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/restart-compare.json"
```

重启后应立即恢复 last-good directory，最终回到 `healthy`；若真实目录没有变化，
identity-set hash 应保持一致，Live count 也不能变化。

随后把真实 secret 暂存在同一私有目录，使用受控错误值强制重建进程：

```sh
mv "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE" \
  "$DEVICES_DOGFOOD_DIR/devices-oauth-secret.valid"
install -m 0600 /dev/null "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
printf '%s\n' 'controlled-invalid-secret' \
  >"$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
chmod 0444 "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d --force-recreate server
```

等待 `stale`，保存 `stale-devices.json` 并执行：

```sh
capture_devices stale stale
scripts/sanitize-devices-dogfood.sh compare stale \
  "$DEVICES_DOGFOOD_DIR/raw/restart-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/stale-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/stale-compare.json"
```

要求 error category 为固定的 `unauthorized` 或 `forbidden`，device count、
identity-set hash 和 content hash 都不变，且 `lastGoodPreserved=true`。API error/log 不得包含 raw
response body 或错误 secret。

恢复真实 secret、force-recreate、等待 `healthy`，然后保存并 sanitize recovered
Devices/topology。要求 Live isolation 仍成立，日志不含 credential：

```sh
rm "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
mv "$DEVICES_DOGFOOD_DIR/devices-oauth-secret.valid" \
  "$TAILPATH_DEVICES_OAUTH_CLIENT_SECRET_FILE"
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml up -d --force-recreate server
capture_devices recovered healthy
```

## Token renewal

以 `recovered-devices.json` 作为私有 baseline，同一 server process 和 secret 连续运行
超过 65 分钟；期间不能重启 container。至少 70 分钟后保存
`renewed-devices.json` 和 topology，并执行：

```sh
capture_devices renewed healthy
scripts/sanitize-devices-dogfood.sh compare renewal \
  "$DEVICES_DOGFOOD_DIR/raw/recovered-devices.json" \
  "$DEVICES_DOGFOOD_DIR/raw/renewed-devices.json" \
  >"$DEVICES_DOGFOOD_DIR/safe/renewal.json"
```

要求 `after.status=healthy` 且 `successAdvancedSeconds >= 3900`。只有 operator 确认
真实目录在窗口内发生变化时，identity-set hash 才允许变化。这个 gate 验证的是 token
过期后的新 OAuth request，而不只是 cached directory 仍存在。

## Evidence 与清理

committed ledger 只能包含 candidate SHA、workflow URL、OCI digest、通用平台版本、
duration、count、boolean、固定 error category 和 sanitizer 输出的 SHA-256 identity-set/
content hash。禁止 raw JSON、timestamp、device name、MagicDNS、hostname、IP、tag、NodeKey、
StableNodeID、canonical ID、Tailnet 名称、credential 或 log payload。

人工检查 safe summary 后，只把安全字段写入 ledger。raw 文件始终留在私有目录。最后：

```sh
docker compose -p "$DEVICES_DOGFOOD_PROJECT" \
  -f compose.yaml -f compose.devices.yaml down -v --remove-orphans
case "$DEVICES_DOGFOOD_DIR" in
  /tmp/tailpath-v05-devices-dogfood.??????) rm -rf -- "$DEVICES_DOGFOOD_DIR" ;;
  *) echo "refusing unexpected evidence path" >&2; exit 1 ;;
esac
```

qualification 完成后 revoke 专用 OAuth client 与 tsnet key。Tag 和 Release 始终由人执行。
