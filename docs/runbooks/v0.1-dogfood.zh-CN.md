# v0.1 被动式 dogfood 手册

[English version](v0.1-dogfood.md)

状态：可选的跨宿主机运行环境验证，等待操作者选择 hosts。
[真实 Tailnet 容器 smoke](v0.1-container-smoke.zh-CN.md) 已通过受控、可丢弃网络故障
覆盖必需的 Direct/DERP path transition。

## 目标与边界

本手册在操作者选择的 hosts 之间验证 packaging、原生/Compose collector 与 path
行为。Container smoke 已在单台 Docker host 上验证真实 LocalAPI、tsnet、Direct、
DERP、provenance、lifecycle 和 path transition；本轮是可选的跨宿主机补充，仍不承诺
发现整个 Tailnet。

整个过程必须保持被动边界：

- 不运行 `tailscale ping`、LocalAPI Ping、抓包、路由探测、Tailscale preference
  修改或 ACL/Grants 修改。
- `tailscale ip` 和 `tailscale status --json` 只读取本机运行时状态，可以使用。
- 测试流量是两台 dogfood 节点之间明确发起的 HTTP 文件传输，不是路径探针。
- DERP 使用操作者预先提供的受限网络条件；本手册不安装防火墙规则，也不修改节点
  网络去强制制造 DERP。

不会把可见节点清单解释成完整 Tailnet inventory。

## 拓扑与交付覆盖

```text
             tsnet / WhoIs
 A (native collector) ───────┐
                             ├── S (Compose server image)
 B (host-network collector) ─┘

 A ═════ ordinary HTTP business traffic ═════ B
```

同一个 commit 构建一个带 `dogfood-<sha>` 版本的 image。`S` 使用这个 image 运行
专用 tsnet server；从 image 中提取同一份 Linux binary 给 `A`；`B` 加载同一
image 并通过 `collector` profile 运行。执行前后都校验 binary 和 image checksum。
不得为 dogfood 发布 tag 或 release。

英文手册的“Artifact preparation”给出了逐条命令，并要求：

- checkout 必须 clean，记录完整 commit、binary `version`、binary checksum 和
  image ID；
- evidence 默认放在权限为 0700 的 `/tmp/tailpath-dogfood-evidence.*`，不写入仓库；
- tsnet auth key 只写入 mode-0700 临时目录中的 secret file，首次 enrollment 后
  立即清零；
- `down/up` 重建后确认 container 中只有
  `TS_AUTHKEY=file:/run/secrets/tailscale-authkey`，没有 secret value，并继续使用
  named volume 中的同一份 tsnet identity；
- `docker inspect` 必须确认没有 host/bridge 端口映射；
- server 只能从 Tailnet 的 `http://tailpath-dogfood:8080` 访问。

## Collector 部署

`A` 用校验后的 binary 运行原生 transient systemd service；`B` 用同一 image 和
同 commit 的 `compose.yaml`，只启动 host-network `collector` profile。两者都只读
访问 `/var/run/tailscale/tailscaled.sock`，并通过 Tailnet hostname 上报。

Collector 启动后等待一个 heartbeat interval 加十秒。预期是两个 observer online，
但不能出现 `A/B -> Tailpath` edge。上报连接属于控制流量，必须在首次 receipt
返回 server identity 后从 counter delta 中排除；heartbeat 本身也不能推进 edge。

## 测试序列

### DF-01：空闲与控制流量排除

两边 collector 持续运行，但不产生 `A <-> B` 应用流量。

通过条件：

- `A`、`B` 都显示为 online observer；
- 一个 heartbeat 加十秒后仍没有仅由上报产生的 edge；
- 某个 passive peer 不出现是允许的，runtime observer 不保证完整 inventory。

### DF-02：Direct、双向流量与 provenance

在 `B` 的 Tailscale IPv4 上临时启动 `python3 -m http.server`，提供一个 64 MiB
临时文件；`A` 用 `curl --limit-rate 2M` 下载到 `/dev/null`。临时目录使用
`mktemp -d`，shell trap 负责停止 HTTP server 和删除明确的临时文件。随后交换 A/B
角色再执行一次。

通过条件：

- UI 只产生一条无向逻辑 edge，而不是两条方向 edge；
- 在确认可 Direct 的网络中，当前路径最终为 Direct；
- 正在传输的方向 rate 非零，并与 2 MiB/s 处于合理量级；不能要求 byte 完全相等，
  因为 peer counter 包含该 peer 的其他流量且采样窗口不同；
- 两个 collector 上报后，edge 同时保留 A、B 两份 provenance；若新鲜 evidence
  冲突，UI 要保留冲突而不是静默丢弃。

### DF-03：Active、Recent 与隐藏

停止应用流量，不停止 collector，也不手动刷新浏览器。同时记录 transfer command
退出时间和 edge 最后的 `lastActive`；进程退出后 tailscaled counter 仍可能短暂变化。

通过条件：

- 最后一次实际 byte-counter delta 之后大约 10 秒，速率归零，edge 从 active 变为
  recent；
- 超过服务端配置的两个 heartbeat interval 后 edge 自动消失；
- heartbeat 不延长 edge 生命周期；
- 即使没有新的 SSE topology event，浏览器也会按 `nextChangeAt` 自动刷新。

记录真实时间戳，调度误差允许五秒。

### DF-04：单侧 observation

停止 `B` collector，等待两个 heartbeat interval 加五秒，再执行 `A -> B` HTTP
传输。

通过条件：

- edge 仍能由 `A` 单侧观测到；
- 过期的 `B` provenance 已移除，observation count 为一；
- `B` 不再显示为 online observer。

重启 `B` collector 后再次传输，provenance 应恢复为两份，但不能生成第二个
canonical `B` node。

### DF-05：Server restart 与 SSE 恢复

产生流量、保持 UI 打开，只重启独立 dogfood server container。

通过条件：

- UI 不刷新页面即可回到或保持 live。快速 restart 的 reconnecting 可能短到无法采样，
  因此必须用 resync 后的新 topology update 证明 reconnect；
- recent edge、node alias 和 provenance 从 SQLite runtime state 恢复；
- 生命周期仍以 server receive time 计算，restart 不能把旧 evidence 变 active。
- 两边 collector 完成 hello/resync 后，新的普通应用流量能更新原先打开的 UI。

八天以后 raw report 已淘汰的恢复由自动化 store test 覆盖。这一步验证真实 image、
volume、tsnet state 和浏览器重连，不冒充八天 soak。
Server 不可用或 collector 重建 baseline 期间的流量只提供 best effort 观测，不能用来
断言 outage 期间无损记账。

### DF-06：可选的自然网络 DERP 与路径变更

把 `A`、`B` 放到审批表中已经确认会让普通连接持续走 DERP 的网络条件，然后重复
HTTP 传输。禁止用 active probe 检查或强制路径。

通过条件：

- 当前 edge 变为 DERP，并显示真实 region；
- 最新 server-received traffic report 立即优先于旧 Direct evidence；
- 选中 edge 后，Recent paths 分别显示 Direct 和 DERP 事件及 provenance；
- 恢复正常网络并再次传输后，当前路径回到 Direct。

如果连接自行转成 Direct，这一项记为 inconclusive，需要另找真实受限环境；不能在
本轮临时增加防火墙或 Tailscale debug mutation 来迎合预期。

### DF-07：Observer 与 node aging

停止 `A` collector，并保证没有涉及 `A` 的应用流量。

通过条件：

- 两个 heartbeat interval 后，`A` 不再是 online observer；
- 四个 interval 内没有 report 或 traffic evidence 时，除非有其他新鲜 observation
  支持，`A` 从 live topology 省略；
- 没有本机 observer 的 passive node 只能显示 runtime unknown，不能声称 offline。

### DF-08：暴露面与时钟

通过条件：

- Docker 不发布 host/bridge port；Tailnet 内通过 tsnet + WhoIs 可以读取 API；
- 专用 Tailpath node 不产生控制 edge；
- 时间同步正常的 collector 不显示 clock warning；若真实 collector 偏差超过半个
  heartbeat interval，UI 标记 observer 及其 evidence，但不能为测试去改系统时间。

Wildcard listener 拒绝和 API 未认证行为继续由自动化测试覆盖。为了制造未认证请求而
把安全的 tsnet image 改成宽监听，会测试另一个不安全配置，因此不属于 dogfood。

测试环境。

## Evidence、停止条件与清理

原始 topology JSON 包含 canonical ID 和 direct endpoint，只保存在本地临时 evidence
目录。英文手册提供的 `capture_topology` 会删除 ID 和 direct endpoint，只保留名称、
path kind、DERP region、state、双向 rate、provenance 数量和 clock warning。只有审批
表明确允许的脱敏文件或截图才能附到 public PR。

以下任一情况立即停止并保留本地 evidence：

- Tailpath 尝试 active probe、抓包、policy 或 preference mutation；
- server 出现 Docker host/bridge 端口暴露；
- auth key、raw topology、direct endpoint 或 stable node ID 进入公开附件；
- collector 控制流量形成 edge；
- SQLite migration、runtime restore 或 tsnet identity 复用失败。

清理时停止两个 collector、HTTP server 和 server container，但默认保留隔离 volume，
不能自动执行 `docker compose down -v`。Binary、image、volume 和 raw evidence 只在
操作者接受结果后删除。若 key 不是 ephemeral，最后在控制面撤销，并确认重建后的
container environment 中没有 key。

结果可以更新到 Draft PR，但原始 evidence 留在本地。把 PR 改成 Ready 和 merge 始终
由人决定。
