# v0.1 real-Tailnet container smoke

[中文版](v0.1-container-smoke.zh-CN.md)

Status: the baseline real-Tailnet smoke has passed. The enrolled ephemeral
topology may be reused for the opt-in controlled-DERP extension below.

## Purpose

This is stage one of v0.1 real validation. It creates four independent Tailnet
identities on one Linux Docker host:

```text
tailpath-smoke-server     tsnet server and SQLite
tailpath-smoke-a          tailscaled + collector + HTTP workload
tailpath-smoke-b          tailscaled + collector + HTTP workload
tailpath-smoke-c          tailscaled + passive HTTP workload
```

Each tailscaled node has a separate network namespace, state volume, and
LocalAPI socket. The collectors and HTTP workloads share only their assigned
node's network namespace. Traffic commands use the target's Tailscale IPv4,
never Docker service DNS.

This stage proves real LocalAPI collection, tsnet WhoIs, Direct paths, sparse
control-traffic exclusion, byte-counter rates, two-sided and one-sided
provenance, passive nodes, lifecycle aging, SQLite restart recovery, and SSE
reconnection. The shared Docker underlay normally produces Direct paths. An
explicit test-only UDP fault can additionally validate a real DERP region and
Direct-to-DERP-to-Direct transition; cross-host operational dogfood remains in
the [network-path dogfood runbook](v0.1-dogfood.md).

## Passive boundary

The runner never invokes `tailscale ping`, LocalAPI Ping, packet capture,
preference mutation, or policy mutation. It uses only local status reads and
ordinary rate-limited HTTP transfers between the test nodes.

Workload health checks, API reads, and traffic-generation requests explicitly
bypass inherited HTTP proxy settings. Their destination is reachable only
through the source node's Tailscale network namespace, so a successful transfer
cannot have escaped through a host or corporate proxy.

The opt-in DERP extension changes only the disposable test namespaces. It is a
controlled network fault, not Tailpath runtime behavior or an active path probe.
It preserves DNS UDP, preserves TCP for the Tailscale control plane and DERP,
and is always paired with an explicit rollback. Production collectors and
servers never install or alter firewall rules.

## Auth key contract

The operator supplies one auth key with these properties:

- reusable, because it enrolls the server and three sidecars;
- ephemeral, so disconnected smoke nodes are automatically removed;
- tagged when the Tailnet uses tag-based policy;
- pre-approved when device approval is enabled;
- allowed by existing policy to reach the other smoke identities on TCP 8080
  and 18088.

The input key is written only to `/tmp/tailpath-smoke-authkey` with mode 0600.
After the image build, the runner copies it into a mode-0700 temporary directory
as a mode-0444 Compose secret source. Docker bind-mounts that file so both root
tailscaled sidecars and the image's nonroot server can read it; other host users
cannot traverse the private directory. Service environments expose only
`TS_AUTHKEY=file:/run/secrets/tailscale-authkey`. The runner zeroes both host
copies after all identities enroll, and also zeroes them on failure or
interruption. It never places the key in a command argument, environment value,
log, repository, or evidence file.

## Offline preflight

The checked-in topology is [compose.smoke.yaml](../../compose.smoke.yaml) and
the agent entrypoint is [scripts/smoke.sh](../../scripts/smoke.sh). The default
images are pinned:

- `tailscale/tailscale:v1.102.2`, matching the Go integration version;
- `busybox:1.37.0` for the three HTTP workloads;
- `curlimages/curl:8.12.1` for one-shot traffic generation;
- the local Tailpath image tagged `smoke-<commit>`.

Before receiving a key, validate only syntax and the expanded Compose model
with a placeholder secret. Confirm `/dev/net/tun`, Docker, Compose, and `jq`
are available. The server must have no published port, and the expanded model
must contain only the secret path, not a key value.

This host can use a standalone Compose binary by setting `TAILPATH_COMPOSE`.
The standard default is the Docker Compose plugin.

## Agent execution

The operator gives the key to the agent through the approved secret channel.
The agent creates the mode-0600 temporary file without echoing the value, then
runs:

```sh
scripts/smoke.sh up
```

`up` builds the exact current image, enrolls all four identities, discovers the
server through node A's runtime peer view, starts collectors and workloads, and
zeroes the key file. It configures a 15-second heartbeat so evidence expiry is
30 seconds and node omission is 60 seconds; the production default remains one
minute.

Read-only inspection commands are:

```sh
scripts/smoke.sh status
scripts/smoke.sh topology | jq .
```

Ordinary traffic commands transfer a 64 MiB file at 2 MiB/s, keeping the flow
active across multiple two-second collector samples:

```sh
scripts/smoke.sh traffic a b
scripts/smoke.sh traffic b a
scripts/smoke.sh traffic a c
```

Run a traffic command in one agent session and inspect the topology/UI in
another while it is active. A Tailnet-authorized browser can open
`http://tailpath-smoke-server:8080/`.

Observer and restart controls are explicit:

```sh
scripts/smoke.sh collector stop b
scripts/smoke.sh collector start b
scripts/smoke.sh restart-server
```

## Controlled DERP extension

Tailscale direct connections require UDP, while DERP remains reachable over
TCP 443. To make the A-to-B case deterministic, block non-DNS UDP egress in the
A and B network namespaces only. Their collectors and workloads share those
same namespaces, so no additional containers need mutation. Do not block the
Tailpath server or passive C merely to test A-to-B.

This follows Tailscale's documented
[connection types](https://tailscale.com/docs/reference/connection-types) and
[firewall port requirements](https://tailscale.com/docs/reference/faq/firewall-ports):
Direct uses UDP, while control and DERP data remain available over TCP 443.

Run this in a shell whose trap will restore both namespaces on exit:

```sh
restore_udp() {
  scripts/smoke.sh udp restore a b
}
trap restore_udp EXIT INT TERM

scripts/smoke.sh udp block a b
scripts/smoke.sh udp status a b
scripts/smoke.sh traffic a b
```

While the ordinary HTTP transfer is active, inspect topology and the UI. With
no configured Peer Relay, the edge must settle on DERP and expose its actual
region. If a Peer Relay is configured, relayed traffic may correctly prefer it;
do not call that a DERP failure.

Restore normal UDP, clear the trap, and generate another ordinary transfer:

```sh
scripts/smoke.sh udp restore a b
trap - EXIT INT TERM
scripts/smoke.sh traffic a b
```

The latest traffic-bearing report must change the current edge back to Direct.
The runner never invokes `tailscale ping` or another path probe in either phase.

## Acceptance sequence

1. **Enrollment and isolation:** four distinct identities appear; server has no
   host port; the local secret file is empty after enrollment.
2. **Idle control exclusion:** after one 15-second heartbeat plus five seconds,
   A and B are online observers and no edge exists solely because they report
   to Tailpath.
3. **High versus low traffic:** during A-to-B transfer, one Direct edge shows a
   plausible aggregate rate near 2 MiB/s. Its compact label and logarithmic
   line width are visibly stronger than light background traffic.
4. **Direction and provenance:** B-to-A reverses the active direction without
   creating a second logical edge. After both reports arrive, provenance count
   is two.
5. **Passive node:** A-to-C produces an edge even though C has no collector; C
   remains passive with runtime state unknown rather than offline.
6. **Aging:** about ten seconds after the final observed byte-counter delta,
   the rate becomes zero and the edge is recent. After 30 seconds it disappears
   without a page reload. Tailscaled counters can continue changing briefly
   after the HTTP transfer process exits, so the command exit is not the aging
   clock origin.
7. **One-sided observation:** stop collector B, wait 35 seconds, then transfer
   A-to-B. The edge remains with only A provenance and B is not an online
   observer.
8. **Restart:** restart the tsnet server while the UI is open. The UI reconnects
   automatically and SQLite restores recent topology without re-enrollment.
   Wait for collector hello/resync before generating traffic used as
   post-restart evidence.
9. **Canonical identity:** restarting collector B restores provenance without
   creating a duplicate B node.
10. **Controlled path transition:** after non-DNS UDP is blocked on A and B,
    ordinary A-to-B traffic is observed through DERP with its real region. After
    rollback, new traffic returns the same logical edge to Direct. The newest
    report wins and prior path events remain in history.

## Execution result

The controlled extension passed on 2026-08-23 using image version
`smoke-b540ad3039d6`:

- baseline A-to-B traffic was Direct at approximately 2.10 MB/s with two
  observations;
- both IPv4 and IPv6 rules on A and B reported `blocked-except-dns`;
- ordinary A-to-B HTTP traffic changed the current path to DERP region `hkg`
  with two observations and sampled application throughput around 161 KB/s;
- the rollback restored all four firewall states to `open`;
- new HTTP traffic changed the same logical edge back to Direct at approximately
  2.25 MB/s, and history retained both path kinds.

The 64 MiB DERP transfer was stopped after sustained application traffic had
been observed because relay throughput was below the 2 MiB/s cap. The shell
trap performed the documented rollback; this does not weaken the path assertion.

Raw topology includes stable identifiers and endpoints and remains local.
Public evidence uses the sanitizer defined in the stage-two runbook.

Traffic while the central server is unavailable, or while a collector is
rebuilding its hello baseline, is best effort and can be absent from reported
deltas. v0.1 does not buffer reports durably on collectors; this smoke validates
recovery after resync rather than lossless outage accounting.

## Cleanup

After evidence is accepted, run the explicit cleanup command:

```sh
scripts/smoke.sh down
```

It logs out sidecars A, B, and C, removes only the isolated
`tailpath-smoke` containers and volumes, and deletes the empty generated
Compose-secret directory and default auth/runtime files. A custom
operator-managed input auth file is zeroed but not deleted. The ephemeral tsnet
server might remain visible in the control plane briefly until Tailscale removes
the disconnected node. Do not revoke the operator's reusable key automatically;
revocation is an operator decision.

Any required smoke discrepancy keeps the PR in Draft. The controlled extension
validates Tailscale's real DERP data path and Tailpath's path reporting; the
multi-host runbook remains a separate operational-environment exercise.
