# v0.3 real Peer Relay dogfood

[中文版](v0.3-peer-relay-dogfood.zh-CN.md)

This runbook qualifies one immutable `main` artifact against a real Linux Peer
Relay. It is an operator procedure, not an automated test. Do not run restart
or traffic steps without an agreed maintenance window and control of every
client in scope.

## Passive and privacy boundary

- Use only ordinary HTTP or iperf application traffic.
- Do not run `tailscale ping`, capture packets, change ACLs/Grants/Peer Relay
  policy, block UDP, or invoke a LocalAPI preference or mutation route.
- A human may move a controlled client between its normal network attachments
  to produce a natural path change. If Tailscale does not select Peer Relay,
  record the case as not exercised; do not force it with policy or firewall
  changes.
- Use anonymous roles in retained evidence: `S` server, `R` relay, `O1/O2`
  observable endpoints, and `P1/P2` passive endpoints without collectors.
- Raw topology and role mappings are private working data. Keep them in a
  mode-0700 temporary directory outside the repository and delete them after
  the redacted ledger is accepted.

## Required topology

| Role | Requirement |
| --- | --- |
| `S` | Existing Compose server with its named data volume |
| `R` | Linux Peer Relay using tested Tailscale v1.102.2 or a separately reviewed compatible version |
| `O1/O2` | Controlled clients with ordinary Tailpath collectors |
| `P1/P2` | Controlled clients without Tailpath collectors |

The Tailnet must already configure `R` as a Peer Relay. This procedure does not
create or alter that configuration. At least one ordinary application service
must be available between each client pair being tested.

## Candidate record

Start only after all v0.3 implementation PRs are on `main` and the matching
main CI run is successful. Create private evidence storage:

```sh
export CANDIDATE_SHA=<full-main-commit-sha>
export MAIN_RUN_ID=<successful-main-ci-run-id>
export EVIDENCE_DIR="$(mktemp -d /tmp/tailpath-relay-dogfood.XXXXXX)"
chmod 0700 "$EVIDENCE_DIR"
```

Verify that the run belongs to the exact commit, download its collector
archives, and resolve the immutable image. Do not use the mutable `edge` tag:

```sh
gh run view "$MAIN_RUN_ID" --json headSha,conclusion \
  | jq -e --arg sha "$CANDIDATE_SHA" '.headSha == $sha and .conclusion == "success"'
gh run download "$MAIN_RUN_ID" --name native-collector-archives \
  --dir "$EVIDENCE_DIR/archives"
(cd "$EVIDENCE_DIR/archives" && sha256sum -c checksums.txt)
docker buildx imagetools inspect \
  "ghcr.io/ghostflying/tailpath:edge-$CANDIDATE_SHA"
```

Record only the commit, CI URL, image digest, archive filename, archive
checksum, architecture, distribution, and Tailscale version in the final
ledger. A digest or checksum mismatch starts a new candidate.

## Preflight

1. Confirm every role is controlled by the operator and no unrelated traffic
   will be mistaken for test traffic.
2. Verify `S`, `R`, and both observable collectors are healthy.
3. Confirm the SSH host key for `R` out of band before adding it to
   `known_hosts`. Never bypass host-key checking.
4. On `R`, extract the matching archive and run the passive diagnostic once:

   ```sh
   ./tailpath collector --check --relay-telemetry=auto \
     | scripts/sanitize-relay-dogfood.sh collector-check \
     > "$EVIDENCE_DIR/relay-check.json"
   ```

   Require `relayCapability=enabled` and `relayEnabled=true`. The current
   session count may be zero. If capability is unsupported, disabled, or
   transient, stop and retain only the sanitized diagnostic.
5. Record the current server image ID/reference and make it locally reachable
   as a rollback candidate. Confirm the named data volume contains both the
   SQLite database and `tsnet/` state. Never use `docker compose down -v`.
6. Copy the current relay collector binary to a root-only rollback path on `R`.

## Upgrade order

### 1. Server first

Pin Compose to `edge-$CANDIDATE_SHA`, pull, and recreate only the server:

```sh
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
docker compose pull server
docker compose up -d --no-deps server
docker compose ps server
```

Verify health, embedded version, unchanged tsnet identity, retained History,
and successful reports from the old `O1/O2` collectors. This proves protocol-v1
backward compatibility before `R` is upgraded. Roll back the server immediately
if identity, database, History, or ordinary collection changes unexpectedly.

### 2. Relay collector

Install the exact archive from the candidate CI run. The installer preserves an
existing config, so explicitly ensure the root-only config contains
`TAILPATH_RELAY_TELEMETRY="auto"` and the existing server URL, then restart only
the collector:

```sh
sudo ./install.sh --server-url <existing-tailnet-server-url>
sudo systemctl restart tailpath-collector.service
sudo systemctl is-active tailpath-collector.service
```

Run the sanitized `--check` again. Do not retain journal lines that contain
names or addresses; record only service active state, recovery count, bounded
retry behavior, and the sanitized diagnostic.

## Evidence capture

Fetch topology from an authorized Tailnet node into the private directory.
Select the target logical edge ID using the private role mapping, then sanitize
it without placing the ID in retained output:

```sh
chmod 0600 "$EVIDENCE_DIR/roles.json"
curl --fail --silent http://<server-tailnet-name>:8080/api/v1/topology \
  > "$EVIDENCE_DIR/topology.raw.json"
scripts/sanitize-relay-dogfood.sh topology <scenario> <private-edge-id> \
  < "$EVIDENCE_DIR/topology.raw.json" \
  > "$EVIDENCE_DIR/<scenario>.json"
```

The sanitizer emits no node, relay, observer, session, or endpoint identifiers.
Inspect every output before sharing it. UI screenshots are optional and must be
redacted outside the repository; a raw screenshot is never accepted as
evidence.

## Scenarios

Stop application traffic between scenarios and wait for the current edge to
age before assigning the next role pair.

| Scenario | Ordinary traffic | Expected evidence |
| --- | --- | --- |
| `two-observable` | `O1` to/from `O2` through `R` | one Peer Relay logical edge; endpoint plus relay provenance; traffic not summed |
| `one-observable` | `O1` to/from `P1` through `R` | one Peer Relay logical edge; one endpoint observer plus relay provenance |
| `no-collector` | `P1` to/from `P2` through `R` | one Peer Relay logical edge from relay provenance alone; honest resolved/partial/anonymous status |

For each scenario, verify Live direction/rate, explicit relay anatomy, VNI
presence, identity status, observer count, and the matching History transition.
Unknown identity is a valid result; guessing or creating relay-to-client
business edges is a failure.

## Direct to Peer Relay to Direct

1. Generate ordinary bidirectional traffic between controlled clients while a
   natural Direct path exists; capture sanitized `path=direct` evidence.
2. Stop traffic. A human moves one client to a controlled network attachment
   where the already configured Tailnet naturally uses `R`.
3. Resume the same ordinary traffic and require a single `path=peer_relay`
   logical edge with relay provenance.
4. Stop traffic, restore the original client attachment, resume traffic, and
   require `path=direct` again.
5. Verify History records Direct, Peer Relay, Direct in receive-time order.

Do not proceed if the transition would require a Tailpath probe, firewall
fault, or control-plane policy change.

## Restart gates

Run each step separately with rollback available:

1. With application traffic stopped, restart the collector on `R`. Its first
   relay sample is a baseline and must not create traffic. Resume traffic and
   require only new deltas plus one recovery transition.
2. Stop traffic and restart `tailscaled` on `R`, which restarts the real relay
   data source. After it and the collector recover, resume traffic and verify
   the same canonical edge without catch-up bytes.
3. Restart only `S`. Confirm the same tsnet identity/data volume, restored Live
   topology, retained History, and collector full resync without offline replay.

Any identity split, fabricated catch-up traffic, lost History, leaked endpoint,
or unbounded retry is a blocker.

## Final audit and rollback

The redacted ledger must state pass/fail/not-exercised for every scenario and
restart. Search retained files for known names, suffixes, addresses, stable
IDs, session IDs, endpoints, and credentials. Delete raw topology, role maps,
and raw logs after the audit.

Keep the old server image and relay collector binary until all gates pass. To
roll back, pin Compose to the recorded prior image and recreate only `server`;
restore the root-only collector backup, reload systemd, and restart only the
collector. Do not roll back a database migration unless its compatibility was
explicitly reviewed; v0.3 adds no supported backup/restore contract.
