# v0.3 Peer Relay container dogfood

[Chinese version](v0.3-peer-relay-dogfood.zh-CN.md)

This runbook qualifies Tailpath against real Tailscale control-plane,
WireGuard, Peer Relay, LocalAPI, and application traffic in a disposable
container Tailnet. It does not require or modify a long-lived relay host.

## Boundaries

- Use only ordinary HTTP workload traffic. Never call `tailscale ping`, capture
  packets, or invoke LocalAPI mutation routes from Tailpath.
- The harness may enable Peer Relay and change firewall rules only inside its
  disposable containers. It does not directly edit host firewall rules, ACLs,
  Grants, or unrelated Tailnet nodes; Docker may manage host netfilter while
  creating and removing the disposable bridge network.
- During relay mode, endpoint namespaces allow DNS, direct UDP to the Tailpath
  server, and the relay UDP port. This isolates the business path without
  turning collector delivery into relay traffic.
- Raw topology, node identities, addresses, endpoints, and session IDs remain
  in a mode-0700 directory outside the repository. Retain only sanitizer output.
- The reusable auth key is staged in a mode-0600 file. `up` zeroes the original
  and Compose copy immediately after enrollment and before workload traffic.

## Tailnet prerequisite

Use a dedicated Tailnet or dedicated ephemeral tag. Its policy must let the
disposable clients use the disposable relay through the application capability:

```json
{
  "src": ["tag:tailpath-smoke"],
  "dst": ["tag:tailpath-smoke"],
  "app": {
    "tailscale.com/cap/relay": []
  }
}
```

Only the `R` container enables relay-server functionality. A differently
scoped but equally narrow Grant is acceptable.

## Candidate gate

The final run uses a successful `main` workflow that published both
`edge-<full-sha>` and matching native archives. Record the workflow URL, image
digest, archive names, and checksums before enrollment. A mutable `edge` tag,
branch tag, or short SHA is not a final candidate.

If GHCR requires authentication, isolate Docker's credential state in a
temporary directory. Then stage the ephemeral key interactively:

```sh
export CANDIDATE_SHA=<40-character-main-sha>
export TAILPATH_VERSION="edge-$CANDIDATE_SHA"
export DOCKER_CONFIG="$(mktemp -d /tmp/tailpath-docker-config.XXXXXX)"
chmod 0700 "$DOCKER_CONFIG"
gh auth token | docker login ghcr.io -u "$(gh api user --jq .login)" --password-stdin

install -m 600 /dev/null /tmp/tailpath-smoke-authkey
IFS= read -r -s AUTH_KEY
printf '%s\n' "$AUTH_KEY" > /tmp/tailpath-smoke-authkey
unset AUTH_KEY
```

For harness development only, omit `TAILPATH_VERSION`; `up` builds a local
`smoke-<branch-sha>` image. Such a run cannot satisfy the final artifact gate.

## Topology lifecycle

Start five ephemeral Tailscale nodes: tsnet server `S`, Peer Relay `R`, and
endpoints `A/B/C`. Endpoint collectors run on `A/B`; relay telemetry runs on
`R`; `C` has no collector.

```sh
scripts/smoke.sh up
scripts/smoke.sh relay-check
```

After `up` has pulled the immutable image, remove the temporary Docker login:

```sh
docker logout ghcr.io
find "$DOCKER_CONFIG" -type f -delete
rmdir "$DOCKER_CONFIG"
unset DOCKER_CONFIG
```

`relay-check` must report `relayCapability=enabled` and `relayEnabled=true`.
The session count may be zero. Confirm the key files are zero bytes before
continuing. If enrollment or capability detection fails, run `down`; do not
weaken the test or modify policy from the harness.

## Direct baseline

```sh
scripts/smoke.sh traffic a b
scripts/smoke.sh path a b
```

While the transfer is active, the passive path must be `direct`. Topology must
contain one active `A-B` business edge with positive directional traffic and
two endpoint observations.

## Peer Relay transition

Stop workload traffic, isolate only endpoint UDP, then resume the same HTTP
transfer:

```sh
scripts/smoke.sh udp relay a b
scripts/smoke.sh traffic a b
scripts/smoke.sh path a b
```

The path must become `peer_relay`. The `A-B` edge must expose a relay identity,
VNI, positive traffic in both directions, two endpoint observations, and one
relay-session observation without summing duplicate traffic.

The relay collector can also observe collector-to-server sessions if that
control path itself uses Peer Relay. The harness deliberately keeps `A-S` and
`B-S` direct so the business assertion remains unambiguous. This does not make
those control sessions non-traffic in a natural deployment.

## Provenance matrix

Allow endpoint observations to age out after each collector stop, then generate
new traffic over the existing relay path:

| Scenario | Collectors | Expected `A-B` provenance |
| --- | --- | --- |
| `two-observable` | `A`, `B`, `R` | three observations, one relay session |
| `one-observable` | `A`, `R` | two observations, one relay session |
| `no-collector` | `R` | one relay-session observation |

```sh
scripts/smoke.sh collector stop b
# wait beyond the server evidence window, then transfer a -> b
scripts/smoke.sh collector stop a
# wait again, then transfer a -> b
```

Relay-only traffic must remain directional and must not create a relay-to-client
business edge. Resolved, partial, or anonymous client identity is acceptable;
false identity merging is not.

## Restart gates

Stop workload traffic before every restart.

```sh
scripts/smoke.sh collector restart r
scripts/smoke.sh restart-relay
scripts/smoke.sh restart-server
```

- Relay collector restart must baseline existing counters and report only new
  bytes after traffic resumes.
- `restart-relay` restarts the relay container and then reattaches the collector
  sidecar to Docker's replacement network namespace. Clients may temporarily
  fall back to DERP or unknown while control-plane relay state converges. Poll
  passive status for at most 90 seconds, then start a new workload connection
  only after `peer_relay` returns. The canonical business edge must remain
  stable and no catch-up spike may appear.
- Server restart must preserve its tsnet identity, named volume, Live topology,
  and History.

## Restore Direct and History

```sh
scripts/smoke.sh udp restore a b
scripts/smoke.sh collector start a
scripts/smoke.sh collector start b
scripts/smoke.sh traffic a b
scripts/smoke.sh path a b
```

The current path must return to `direct`. History detail for the same canonical
edge must contain the exercised transition as an ordered subsequence:

```text
direct -> peer_relay -> direct
```

Additional genuine transitions caused by restart recovery or fresh competing
provenance must remain visible rather than being rewritten out of History.

For the relay-underlay privacy gate, stop the endpoint collectors, wait for
their evidence to expire, and send relay-only traffic between `A` and passive
endpoint `C`. `C` must never have contributed an ordinary Direct observation in
this database. Copy SQLite, WAL, and SHM to the private evidence directory and
scan all three for `C`'s disposable underlay address. A match is a privacy
blocker. Do not use `A` or `B` for this canary: ordinary Direct endpoints are
intentionally durable and would make that test ambiguous.

## Evidence and cleanup

Select the private business edge ID from raw topology and pass it through the
fail-closed sanitizer:

```sh
scripts/sanitize-relay-dogfood.sh topology <scenario> <private-edge-id> \
  < topology.raw.json > scenario.json
```

The retained ledger records only candidate SHA/workflow/digests, Tailscale and
container architectures, pass/fail status, path/state, positive-direction
booleans, relay/VNI presence, provenance counts, identity-status classes, and
clock-skew status.

Always finish with:

```sh
scripts/smoke.sh down
```

`down` logs out the disposable nodes, removes only the `tailpath-smoke` project
containers and volumes, zeroes/removes staged credentials, and removes its
runtime file. Revoke the reusable key after the final run.
