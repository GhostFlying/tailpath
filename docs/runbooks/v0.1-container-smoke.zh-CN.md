# v0.1 真实 Tailnet 容器 Smoke

[English version](v0.1-container-smoke.md)

状态：基础真实 Tailnet smoke 已通过；已 enrollment 的 ephemeral topology 可以继续
用于下文 opt-in 的受控 DERP 扩展。

## 目标

这是 v0.1 真实验证的第一阶段。在同一台 Linux Docker server 上创建四个独立的
Tailnet identity：

```text
tailpath-smoke-server     tsnet server + SQLite
tailpath-smoke-a          tailscaled + collector + HTTP workload
tailpath-smoke-b          tailscaled + collector + HTTP workload
tailpath-smoke-c          tailscaled + passive HTTP workload
```

每个 tailscaled node 都有独立 network namespace、state volume 和 LocalAPI socket。
Collector 和 HTTP workload 只共享自己所属 node 的 network namespace。Traffic
命令访问目标的 Tailscale IPv4，不使用 Docker service DNS。

这一阶段真实验证 LocalAPI collection、tsnet WhoIs、Direct、控制流量排除、byte
counter rate、双侧/单侧 provenance、passive node、lifecycle aging、SQLite restart
和 SSE reconnect。共享 Docker underlay 通常产生 Direct；显式的测试专用 UDP fault
还可以验证真实 DERP region 与 Direct -> DERP -> Direct transition。跨宿主机的运行
环境验证仍保留在[受限网络 dogfood](v0.1-dogfood.zh-CN.md)。

## 被动边界

Runner 不调用 `tailscale ping`、LocalAPI Ping、抓包、preference mutation 或 policy
mutation，只读取本机 status，并在 smoke node 之间传输普通限速 HTTP 文件。

Workload healthcheck、API 读取和 traffic-generation request 会显式绕过继承的 HTTP
proxy。它们的 destination 只能从 source node 的 Tailscale network namespace
访问，因此成功传输不可能经由宿主机或公司 proxy 绕行。

Opt-in DERP 扩展只修改可丢弃的测试 network namespace。这是受控网络故障，不是
Tailpath runtime 行为或 active path probe。它保留 DNS UDP，并保留 Tailscale 控制面
和 DERP 所需的 TCP，且必须搭配显式 rollback。生产 collector/server 永远不会安装
或修改 firewall rule。

## Key 约束与处理

你提供一个具备以下属性的 key：

- reusable：需要 enrollment server 和三个 sidecar；
- ephemeral：container 离线后由 Tailscale 自动删除 node；
- Tailnet 使用 tag policy 时带测试 tag；
- Tailnet 开启 device approval 时为 pre-approved；
- 现有 policy 允许 smoke identity 之间访问 TCP 8080 和 18088。

Agent 只把输入 key 写入 mode 0600 的 `/tmp/tailpath-smoke-authkey`。Image build
完成后，runner 把它复制到 mode 0700 的临时目录，作为 mode 0444 的 Compose secret
source。Docker bind-mount 该文件后，root tailscaled sidecar 和 image 内的 nonroot
server 都可读取；宿主机其他用户无法穿过私有目录。Environment 只出现
`TS_AUTHKEY=file:/run/secrets/tailscale-authkey`，不出现 key value。所有 identity
enrollment 后 runner 立即清零两个宿主副本；image pull、enrollment、ACL 检查失败或
进程被中断时，EXIT/INT/TERM trap 同样清零。Key 不进入 command argument、普通 env
value、log、仓库或 evidence。

## 已准备的拓扑

Compose 在 [compose.smoke.yaml](../../compose.smoke.yaml)，agent 入口在
[scripts/smoke.sh](../../scripts/smoke.sh)。默认 pin：

- `tailscale/tailscale:v1.102.2`，与项目 Tailscale Go integration 对齐；
- `busybox:1.37.0`，提供三个 HTTP workload；
- `curlimages/curl:8.12.1`，产生一次性普通流量；
- 当前 commit 构建的 `smoke-<commit>` Tailpath image。

收到 key 之前只做离线校验：shell 语法、Compose 展开、`/dev/net/tun`、Docker、
Compose 和 `jq` 可用性。Server 不得发布 host port；展开后的 model 只能包含 secret
路径。这台 server 当前可通过 `TAILPATH_COMPOSE` 指定 standalone Compose v5.5.0，
标准环境默认使用 `docker compose` plugin。

## Agent 执行方式

收到 key 后，agent 通过安全输入创建临时文件，不回显 value，然后执行：

```sh
scripts/smoke.sh up
```

`up` 会构建当前 commit、enroll 四个 identity、从 A 的 runtime peer view 找到 tsnet
server、启动 collector/workload，最后清零 key。Smoke 使用 15 秒 heartbeat，因此
evidence expiry 是 30 秒，node omission 是 60 秒；生产默认值仍是一分钟。

只读状态：

```sh
scripts/smoke.sh status
scripts/smoke.sh topology | jq .
```

普通流量命令每次通过 Tailscale IPv4 传输 64 MiB，并限速 2 MiB/s，保证跨越多个
两秒采样窗口：

```sh
scripts/smoke.sh traffic a b
scripts/smoke.sh traffic b a
scripts/smoke.sh traffic a c
```

Traffic 在一个 agent session 中运行，另一个 session 同时读取 topology 或 UI。
Tailnet 内有权限的浏览器可以打开 `http://tailpath-smoke-server:8080/`。

显式 observer/restart 控制：

```sh
scripts/smoke.sh collector stop b
scripts/smoke.sh collector start b
scripts/smoke.sh restart-server
```

## 受控 DERP 扩展

Tailscale Direct 需要 UDP，DERP 则仍可通过 TCP 443 到达。为了让 A -> B 确定性地
进入 relay，只在 A、B 两个 network namespace 阻断非 DNS 的 UDP egress。各自的
collector/workload 已共享相同 namespace，不需要再修改别的 container；测试 A -> B
时不应无谓阻断 Tailpath server 或 passive C。

这与 Tailscale 官方的
[connection types](https://tailscale.com/docs/reference/connection-types) 和
[firewall port requirements](https://tailscale.com/docs/reference/faq/firewall-ports)
一致：Direct 使用 UDP，控制面与 DERP data 仍可通过 TCP 443 使用。

在带 rollback trap 的 shell 中执行：

```sh
restore_udp() {
  scripts/smoke.sh udp restore a b
}
trap restore_udp EXIT INT TERM

scripts/smoke.sh udp block a b
scripts/smoke.sh udp status a b
scripts/smoke.sh traffic a b
```

普通 HTTP transfer 活跃期间读取 topology/UI。如果 Tailnet 没有配置 Peer Relay，edge
必须稳定为 DERP 并显示真实 region；如果配置了 Peer Relay，relay 流量可能正确地优先
使用它，不能据此判定 DERP 实现失败。

恢复正常 UDP、清除 trap，再产生一次普通流量：

```sh
scripts/smoke.sh udp restore a b
trap - EXIT INT TERM
scripts/smoke.sh traffic a b
```

最新的 traffic-bearing report 必须把当前 edge 改回 Direct。两个阶段都不能调用
`tailscale ping` 或其他 path probe。

## 验收顺序

1. **Enrollment/隔离：**出现四个不同 identity；server 没有 host port；本地 secret
   文件 enrollment 后为空。
2. **控制流量排除：**等待一个 15 秒 heartbeat 加五秒，A/B 都是 online observer，
   但上报本身没有形成 edge。
3. **高速与轻流量：**A -> B 传输时只有一条 Direct edge，总速率在 2 MiB/s 合理
   范围内；compact label 和对数线宽应明显强于零星背景流量。
4. **方向/provenance：**B -> A 改变 active 方向但不产生第二条逻辑 edge；两边上报
   后 provenance count 为二。
5. **Passive node：**A -> C 仍产生 edge；C 没有 collector，因此只能显示 passive
   和 runtime unknown，不能显示 offline。
6. **Aging：**最后一次实际 byte-counter delta 之后约十秒，rate 归零、edge 变
   recent；30 秒后不刷新页面也会自动消失。HTTP transfer 进程退出后，tailscaled
   counter 仍可能短暂变化，因此不能把 command exit 当作 aging 起点。
7. **单侧 observation：**停止 collector B，等待 35 秒，再执行 A -> B；edge 仍在，
   但只有 A provenance，B 不再是 online observer。
8. **Restart：**UI 打开时重启 tsnet server；UI 自动 reconnect，SQLite 恢复 recent
   topology，所有 identity 不需要重新 enrollment。用于验证 restart 后恢复情况的
   流量，必须等 collector hello/resync 完成后再生成。
9. **Canonical identity：**重启 collector B 后 provenance 恢复，但不能生成重复 B。
10. **受控 path transition：**A/B 阻断非 DNS UDP 后，普通 A -> B 流量通过 DERP
    被观测到并显示真实 region；rollback 后的新流量把同一 logical edge 恢复为
    Direct。最新 report 优先，旧 path event 保留在 history。

## 执行结果

受控扩展已于 2026-08-23 使用 image version `smoke-b540ad3039d6` 通过：

- 基线 A -> B 为 Direct，约 2.10 MB/s，两份 observation；
- A/B 的 IPv4、IPv6 rule 都显示 `blocked-except-dns`；
- 普通 A -> B HTTP 流量把当前路径改为 DERP region `hkg`，保留两份 observation，
  实际应用吞吐采样约 161 KB/s；
- rollback 把四项 firewall 状态全部恢复为 `open`；
- 新 HTTP 流量把同一 logical edge 恢复为 Direct，约 2.25 MB/s，history 同时保留
  两类 path。

DERP 吞吐低于 2 MiB/s cap，因此在持续应用流量已经被观测后停止了 64 MiB transfer；
shell trap 执行了文档规定的 rollback，这不影响 path assertion。

Raw topology 包含 stable identifier 和 endpoint，只保存在本地；公开 evidence 使用
第二阶段 runbook 中定义的 sanitizer。

中央 server 不可用或 collector 正在重建 hello baseline 时产生的流量只提供 best
effort 观测，可能不会出现在 delta 中。v0.1 不在 collector 侧持久化排队 report；本
smoke 验证 resync 后的恢复能力，不承诺 outage 期间无损记账。

## 清理

Evidence 确认后显式执行：

```sh
scripts/smoke.sh down
```

它会 logout A/B/C，只删除隔离的 `tailpath-smoke` containers/volumes、空的临时
Compose-secret 目录，以及本地默认 auth/runtime 文件；操作者自定义的输入 auth
文件只清零、不删除。Ephemeral tsnet server 可能短暂保留在控制面，随后由
Tailscale 删除。Runner 不自动 revoke reusable key，是否撤销由你决定。

任一必需 smoke 项失败，PR 保持 Draft。受控扩展验证 Tailscale 的真实 DERP data
path 和 Tailpath path reporting；多宿主机 runbook 仍是独立的运行环境验证。
